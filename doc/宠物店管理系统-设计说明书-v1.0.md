## 1. 设计约束（先看这一节，它决定了后面所有选择）

| 约束 | 来源 | 对设计的影响 |
|---|---|---|
| **JDK 1.8** | 用户指定 | Spring Boot 只能用 2.7.x；**禁用 var / record / switch 表达式 / 文本块 / List.of / isBlank**；`javax.*` 命名空间 |
| **双击 bat 启动** | 用户指定 | 必须单 fat jar、自检 Java、自动建目录、工作目录锚定 `%~dp0` |
| **SQLite 单文件** | 用户指定 | 全库无小数类型 → 金额用分；单写入模型 → 连接池 ≤ 4 + WAL |
| **MyBatis（非 Plus）** | 用户指定 | 手写 XML，SQL 可控；分页手写 `COUNT` + `LIMIT` |
| **Thymeleaf 服务端渲染** | 已定 | 无前后端分离，无 REST 契约层，省 12h |
| **不接热敏打印** | 用户指定 | 单据只做浏览器 `Ctrl+P`，不引任何打印 SDK |
| **门店可能断网** | 业务 | 所有静态资源本地化，**零 CDN** |

### 1.1 JDK 1.8 禁用 API 清单（写完自查）

| 禁用 | 替代 |
|---|---|
| `var` | 显式类型 |
| `record` / `sealed` / `instanceof` 模式匹配 | 普通类 + 强制转换 |
| `switch` 箭头表达式 | 传统 `switch` + `break` |
| `"""` 文本块 | 字符串拼接 |
| `List.of()` / `Map.of()` / `Set.of()` | `Arrays.asList()` / `Collections.unmodifiableList` / `new HashMap<>()` |
| `String.isBlank()` / `strip()` / `repeat()` | `trim().isEmpty()` / `trim()` |
| `Optional.isEmpty()` | `!opt.isPresent()` |
| `Files.readString()` / `writeString()` | `new String(Files.readAllBytes(p), StandardCharsets.UTF_8)` |
| `Stream.toList()` | `collect(Collectors.toList())` |
| `java.net.http.HttpClient` | `HttpURLConnection`（本版不用） |

**可放心用**：Lambda、Stream、`Optional`、`java.time`（`LocalDate` / `LocalDateTime` / `Duration`）、`CompletableFuture`（本版不用）。

## 3. 系统架构

### 3.1 分层

```
浏览器（Thymeleaf 渲染的 HTML + Alpine.js）
        │  HTTP（同源，无跨域）
        ▼
┌─────────────────────────────────────────┐
│ Controller 层  @Controller 返回视图名     │  ← 参数校验、权限判断、调用 Service
├─────────────────────────────────────────┤
│ Service 层     @Transactional 事务边界    │  ← 业务规则 BR-01..BR-08 全部在这里
├─────────────────────────────────────────┤
│ Mapper 层      MyBatis 接口 + XML         │  ← 只写 SQL，不含业务判断
└─────────────────────────────────────────┘
        │  JDBC（HikariCP，最大 4 连接）
        ▼
   SQLite  data/pet.db（WAL 模式）
```

**三条分层纪律**：
1. **Controller 不写业务逻辑**，方法体不超过 15 行，只做「取参 → 调 Service → 放 model → 返视图」
2. **Mapper 不写业务判断**，`if` 只用于动态 SQL 拼条件，不用于决定业务分支
3. **事务边界在 Service**，`@Transactional(rollbackFor = Exception.class)` —— 必须显式写 `rollbackFor`，否则受检异常不回滚

### 3.2 包结构

```

├─ common
```

## 4. 配置设计

### 4.1 application.yml（`config/` 下，外置）

```yaml
server:
  port: 8080
  servlet:
    session:
      timeout: 8h
    encoding:
      charset: UTF-8
      force: true

spring:
  application:
    name: pet-shop
  datasource:
    url: jdbc:sqlite:file:./data/pet.db?journal_mode=WAL&busy_timeout=5000&foreign_keys=on
    driver-class-name: org.sqlite.JDBC
    hikari:
      maximum-pool-size: 4
      minimum-idle: 1
      connection-timeout: 5000
      max-lifetime: 0            # SQLite 本地连接无需回收
  sql:
    init:
      mode: always               # 每次启动执行 schema.sql（全部 IF NOT EXISTS，幂等）
      schema-locations: classpath:schema/schema.sql
      data-locations: classpath:schema/data.sql
      continue-on-error: false
  thymeleaf:
    cache: false                 # 开发期 false；打包前改 true
    encoding: UTF-8
    mode: HTML
  mvc:
    hiddenmethod:
      filter:
        enabled: true

mybatis:
  mapper-locations: classpath*:mapper/*.xml
  type-aliases-package: com.petshop.module
  type-handlers-package: com.petshop.handler
  configuration:
    map-underscore-to-camel-case: true
    default-statement-timeout: 10
    cache-enabled: false          # 单机低并发，缓存只会带来脏读

app:
  data-dir: ./data
  backup-dir: ./data/backup
  backup-keep: 7
  business-day-cutoff-hour: 4
  default-admin-password: "123456"
```

### 4.2 三个 JDBC 参数的作用（缺一个都出事）

| 参数 | 作用 | 缺失后果 |
|---|---|---|
| `journal_mode=WAL` | 读不阻塞写，写不阻塞读 | 前台查询时开单会卡住 |
| `busy_timeout=5000` | 遇到锁最多等 5 秒 | 并发写立刻抛 `SQLITE_BUSY` |
| `foreign_keys=on` | 每个连接打开外键约束 | 删客户后宠物变孤儿数据，**SQLite 默认是关的** |

**为什么连接池只有 4**：SQLite 是单写入模型，连接越多抢锁越凶。4 个足够「1 个写 + 3 个读」，调到 20 反而更慢更易报错。

## 5. 数据库设计

### 5.1 SQLite 类型规范（全库必须遵守）

| 逻辑类型 | 物理类型 | 命名约定 | 示例 |
|---|---|---|---|
| 金额 | `INTEGER`（单位：**分**） | `_cent` 后缀 | `price_cent = 12800` 表示 128.00 元 |
| 重量 | `INTEGER`（单位：**克**） | `_g` 后缀 | `weight_g = 4350` 表示 4.35kg |
| 数量 | `INTEGER` | 无后缀 | `qty` |
| 日期 | `TEXT` `yyyy-MM-dd` | `_on` 后缀 | `expire_on = '2027-10-23'` |
| 时间 | `TEXT` `yyyy-MM-dd HH:mm:ss` | `_at` 后缀 | `created_at` |
| 布尔 | `INTEGER` 0/1 | `is_` 前缀 | `is_active` |
| 枚举 | `TEXT` 大写常量 | — | `status = 'ACTIVE'` |

**为什么金额必须是整数**：SQLite 没有 DECIMAL 类型，`DECIMAL(12,2)` 会被归到 NUMERIC 亲和性并实际存成浮点。写 `0.1` 取出来可能不是 `0.1`，对账差几分钱且几乎无法定位。**这条没有例外**。

**为什么不用 `BOOLEAN`**：SQLite 没有布尔类型，JDBC 驱动的映射在各版本间行为不一致，用 `INTEGER` + Java `boolean`（MyBatis 自动转换）最稳。

### 5.2 建表脚本（`resources/schema/schema.sql`）

> 全部使用 `CREATE TABLE IF NOT EXISTS` + `CREATE INDEX IF NOT EXISTS`，保证重复启动不报错。
>
> **关于字段注释**：SQLite **不支持** `COMMENT ON COLUMN` 这类列级注释语法（那是 MySQL / PostgreSQL 的能力），因此本脚本把每个字段的业务含义写成**行内 `--` 注释**。SQL 解释器会忽略它，但人和 AI 读脚本时能直接看懂每一列是干什么的。14 张表、142 个字段，注释覆盖率 100%。
>
> **执行方式**：`--` 行内注释只有按行解析才安全。Spring 的 `DataSourceInitializer` / `ScriptUtils` 可以正确处理；如果自己用 `sql.split(";")` 切分执行，注释会和下一条语句粘连导致语法错误 —— 务必用 `ScriptUtils.executeSqlScript()`。

```sql
-- ============================================================================
-- 宠物店管理系统 · 数据库结构（SQLite 3）
-- 文件位置：src/main/resources/schema/schema.sql
--
-- 【关于注释】SQLite 不支持 MySQL 那种 COMMENT ON COLUMN / 列级 COMMENT 语法，
-- 因此本文件把字段说明统一写成行内 `--` 注释。执行时会被 SQL 解释器忽略，
-- 但对人和 AI 阅读是有效的。任何只认「建表语句本身」的工具也能正常执行。
--
-- 【命名约定】
--   *_cent       金额，单位「分」，INTEGER。禁止 REAL/FLOAT/DOUBLE。
--   *_g          重量，单位「克」，INTEGER。
--   *_on         日期，TEXT 'yyyy-MM-dd'。
--   *_at         时间点，TEXT 'yyyy-MM-dd HH:mm:ss'。
--   is_*         布尔，INTEGER 0/1（SQLite 无布尔类型）。
--   无后缀        数量，INTEGER。
--
-- 【为什么要这么多注释】字段名的语义比类型重要。「used_paid 是已用付费次数
--   还是余额」这种歧义，写在注释里是 5 秒钟的事，写错代码是半天的事。
-- ============================================================================


-- ============================================================================
-- 1. customer 客户档案
--    付费主体。宠物是「被服务对象」，客户是「付钱的人」，一人可多宠。
-- ============================================================================
CREATE TABLE IF NOT EXISTS customer (
  id         INTEGER PRIMARY KEY AUTOINCREMENT, -- 主键，自增
  name       TEXT    NOT NULL,                  -- 客户姓名（或称呼），单据与提醒里显示这个
  phone      TEXT    NOT NULL,                  -- 手机号，全局唯一；查重、召回、熟客识别都靠它
  source     TEXT,                              -- 客户来源渠道（自然到店/朋友介绍/美团/抖音…），自由文本，仅用于统计拉新效果
  remark     TEXT,                              -- 备注：住址、接送习惯、砍价记录、投诉历史等
  is_active  INTEGER NOT NULL DEFAULT 1,        -- 是否有效：1=正常 0=已停用。逻辑删除，名下可能有单据，不可物理删除
  created_at TEXT    NOT NULL                   -- 建档时间 'yyyy-MM-dd HH:mm:ss'
);
CREATE UNIQUE INDEX IF NOT EXISTS uk_customer_phone ON customer(phone); -- 手机号唯一：同一部手机不允许建两个客户，否则次卡余额会分裂


-- ============================================================================
-- 2. pet 宠物档案
--    一个人可以有多只宠物 → owner_id 指向 customer，父子结构。
-- ============================================================================
CREATE TABLE IF NOT EXISTS pet (
  id           INTEGER PRIMARY KEY AUTOINCREMENT, -- 主键，自增
  owner_id     INTEGER NOT NULL REFERENCES customer(id), -- 主人 customer.id；一人多宠靠这个字段体现
  name         TEXT    NOT NULL,                  -- 宠物昵称，叫「豆豆」而不是「编号 7」
  species      TEXT    NOT NULL,                  -- 物种：DOG 狗 / CAT 猫 / OTHER 其他；决定可选品种与疫苗模板
  breed        TEXT,                              -- 品种，如 金毛/泰迪/英短；决定毛型与美容方案
  gender       TEXT,                              -- 性别：MALE 公 / FEMALE 母 / UNKNOWN 未知
  birthday     TEXT,                              -- 生日 'yyyy-MM-dd'。★不存「年龄」字段：年龄必须实时算，否则每天都得过期一次
  weight_g     INTEGER,                           -- 体重，单位克（12.5kg 存 12500）；决定洗护体型档与用药剂量
  is_neutered  INTEGER NOT NULL DEFAULT 0,        -- 是否已绝育：1=是 0=否；影响护理建议与部分服务禁忌
  color        TEXT,                              -- 毛色，美容师认狗用（「白色比熊」比「豆豆」更好认）
  habit        TEXT,                              -- 习性/禁忌：怕吹风机、会咬人、某浴液过敏、不配合剪指甲……出事前的唯一提示
  is_active    INTEGER NOT NULL DEFAULT 1,        -- 是否有效：1=在册 0=已离世/已转让。离世的宠物不能物理删，否则历史单据无法解释
  created_at   TEXT    NOT NULL                   -- 建档时间
);
CREATE INDEX IF NOT EXISTS idx_pet_owner ON pet(owner_id); -- 按主人查宠物列表（开单选宠物、档案详情页）


-- ============================================================================
-- 3. pet_event 免疫/驱虫/体检记录
--    这是整个系统的「复购引擎」：宠物店的回头客不靠促销，靠到期提醒。
-- ============================================================================
CREATE TABLE IF NOT EXISTS pet_event (
  id             INTEGER PRIMARY KEY AUTOINCREMENT, -- 主键，自增
  pet_id         INTEGER NOT NULL REFERENCES pet(id), -- 属于哪只宠物
  event_type     TEXT    NOT NULL,                  -- 事件类型：VACCINE 疫苗 / RABIES 狂犬 / DEWORM 驱虫 / CHECKUP 体检
  happened_on    TEXT    NOT NULL,                  -- 本次发生日期 'yyyy-MM-dd'（上次打针/驱虫那天）
  next_due_on    TEXT,                              -- 下次到期日 'yyyy-MM-dd'。为空表示一次性记录、不进提醒清单；提醒只扫非空行
  hospital       TEXT,                              -- 接种/就诊机构；出问题时客户一定会问「在哪打的」，必须可追溯
  remark         TEXT,                              -- 备注：疫苗批号、品牌、不良反应等
  contact_status TEXT,                              -- 提醒跟进状态：NULL=未处理 / CONTACTED=已联系未成交 / BOOKED=已预约 / DONE=已完成 / IGNORED=不再提醒（客户明确拒绝）
  contacted_at   TEXT,                              -- 最近一次跟进时间。为空表示还没人打过电话
  contacted_by   TEXT,                              -- 跟进人（员工显示名），业绩与追责用
  created_at     TEXT    NOT NULL                   -- 记录创建时间
);
CREATE INDEX IF NOT EXISTS idx_event_due ON pet_event(next_due_on, contact_status); -- 首页「今日到期提醒」按此索引扫描，只取未处理的行


-- ============================================================================
-- 4. service_item 服务项目
--    洗护/美容/药浴等项目，按体型分四档价 —— 这是宠物行业与普通零售最大的差别。
-- ============================================================================
CREATE TABLE IF NOT EXISTS service_item (
  id             INTEGER PRIMARY KEY AUTOINCREMENT, -- 主键，自增
  name           TEXT    NOT NULL,                  -- 服务名称，如「精洗」「剪毛造型」「药浴」
  duration_min   INTEGER NOT NULL DEFAULT 60,       -- 标准耗时（分钟），用于 P1 预约看板算占位；体型越大实际越久，此处为基准值
  price_s_cent   INTEGER NOT NULL DEFAULT 0,        -- 小体型价（≤5kg），单位分；0 表示该体型不接此服务，不是免费
  price_m_cent   INTEGER NOT NULL DEFAULT 0,        -- 中体型价（5–15kg），单位分
  price_l_cent   INTEGER NOT NULL DEFAULT 0,        -- 大体型价（15–30kg），单位分
  price_xl_cent  INTEGER NOT NULL DEFAULT 0,        -- 超大体型价（>30kg），单位分；金毛/阿拉斯加按这档收
  sort_no        INTEGER NOT NULL DEFAULT 0,        -- 排序号，小的在前；开单页按此顺序排列，常用项目排前面
  is_active      INTEGER NOT NULL DEFAULT 1         -- 是否在售：1=可开单 0=已下架。停售不影响历史单据（单据存的是名称快照）
);


-- ============================================================================
-- 5. product 商品
--    狗粮、零食、用品等实物。库存数量存这里，流水记在 product_ledger。
-- ============================================================================
CREATE TABLE IF NOT EXISTS product (
  id              INTEGER PRIMARY KEY AUTOINCREMENT, -- 主键，自增
  name            TEXT    NOT NULL,                  -- 商品名称，含规格（如「皇家A3 幼犬粮 2kg」）；规格要写进名称，否则库存没法区分
  barcode         TEXT,                              -- 条码，可空；扫码枪录入用。一物多码时只存主条码
  sale_price_cent INTEGER NOT NULL DEFAULT 0,        -- 零售价，单位分
  cost_price_cent INTEGER NOT NULL DEFAULT 0,        -- 参考成本价，单位分；仅用于毛利估算与进货提醒，不参与库存计价
  stock_qty       INTEGER NOT NULL DEFAULT 0,        -- 当前库存数量。★这是「结存表」，必须恒等于该商品在 product_ledger 中的 qty_change 之和
  safety_qty      INTEGER NOT NULL DEFAULT 0,        -- 安全库存，低于此值进首页「低库存预警」；0 表示不预警
  expire_on       TEXT,                              -- 有效期至 'yyyy-MM-dd'。★仅适用于「整店单一效期」；同商品多批次不同效期时此字段不可靠，需留空并在 P2 上批次表
  is_active       INTEGER NOT NULL DEFAULT 1,        -- 是否在售：1=可开单 0=已停售
  created_at      TEXT    NOT NULL                   -- 建档时间
);
CREATE INDEX IF NOT EXISTS idx_product_barcode ON product(barcode); -- 扫码枪按条码定位商品


-- ============================================================================
-- 6. product_ledger 库存流水
--    ★ 只允许 INSERT，禁止 UPDATE / DELETE。流水就是证据，改了就无法自证清白。
-- ============================================================================
CREATE TABLE IF NOT EXISTS product_ledger (
  id          INTEGER PRIMARY KEY AUTOINCREMENT, -- 主键，自增
  product_id  INTEGER NOT NULL REFERENCES product(id), -- 变动的是哪个商品
  biz_type    TEXT    NOT NULL,                  -- 变动原因：IN 采购入库 / SALE 销售出库 / RETURN 退货入库 / CANCEL 反结账回滚 / ADJUST 盘点调整
  qty_change  INTEGER NOT NULL,                  -- 变动数量：入库为正、出库为负，不允许 0
  before_qty  INTEGER NOT NULL,                  -- 变动前库存快照；与 after_qty 一起构成完整证据链
  after_qty   INTEGER NOT NULL,                  -- 变动后库存快照；必须满足 after_qty = before_qty + qty_change
  ref_type    TEXT,                              -- 关联单据类型：BILL 销售单 / MANUAL 手工调整
  ref_id      INTEGER,                           -- 关联单据 id；ref_type=BILL 时指向 bill.id
  operator    TEXT,                              -- 操作人（员工显示名）
  remark      TEXT,                              -- 备注：手工调整必须写原因
  created_at  TEXT    NOT NULL                   -- 发生时间；与 product.stock_qty 同事务写入
);
CREATE INDEX IF NOT EXISTS idx_ledger_product ON product_ledger(product_id, created_at); -- 按商品查流水、对账（流水求和 = 结存）


-- ============================================================================
-- 7. card_type 卡类型（卡模板/货架商品）
--    这是「货架上卖的卡」，不是「客户手里那张卡」。改这里不影响已售出的卡。
-- ============================================================================
CREATE TABLE IF NOT EXISTS card_type (
  id          INTEGER PRIMARY KEY AUTOINCREMENT, -- 主键，自增
  name        TEXT    NOT NULL,                  -- 卡名称，如「洗护10次卡（送2次）」
  service_ids TEXT    NOT NULL,                  -- 适用服务项目 id 列表，逗号分隔，如 '3,4,7'；核销时校验，不匹配则拒绝 CARD_NOT_MATCH_SERVICE
  paid_qty    INTEGER NOT NULL,                  -- 付费次数（客户真正掏钱买的部分）
  gift_qty    INTEGER NOT NULL DEFAULT 0,        -- 赠送次数；★必须与 paid_qty 分开记：退款只退 paid 部分，营收只确认 paid 部分
  price_cent  INTEGER NOT NULL,                  -- 售价，单位分
  valid_days  INTEGER NOT NULL DEFAULT 365,      -- 有效天数，自发卡日起算；到期日 = issued_on + valid_days
  is_active   INTEGER NOT NULL DEFAULT 1         -- 是否可售：1=货架可见 0=已停售（不影响已发出的卡）
);


-- ============================================================================
-- 8. customer_card 客户持有的卡
--    ★ 卡是「资产」不是「优惠券」。这里记录的是客户已购得的权利。
--    ★ 剩余次数不存字段！实时算：paid_qty - used_paid + gift_qty - used_gift
--      存了 remaining 就一定会有不同步的那天，而那正是客户投诉「你们这卡有鬼」的来源。
-- ============================================================================
CREATE TABLE IF NOT EXISTS customer_card (
  id               INTEGER PRIMARY KEY AUTOINCREMENT, -- 主键，自增
  card_no          TEXT    NOT NULL,                  -- 卡号，唯一，人可读（规则见设计文档 §7.7）；客户报卡号、纠纷时对账都靠它
  customer_id      INTEGER NOT NULL REFERENCES customer(id), -- 持卡客户
  card_type_id     INTEGER NOT NULL REFERENCES card_type(id), -- 来源卡类型；仅用于展示「这卡是怎么卖的」，次数与金额已在本表固化，不随卡类型改动
  paid_qty         INTEGER NOT NULL,                  -- 本卡付费次数（发卡时从卡类型复制过来的快照，之后不再变）
  gift_qty         INTEGER NOT NULL DEFAULT 0,        -- 本卡赠送次数（同样为发卡时快照）
  used_paid        INTEGER NOT NULL DEFAULT 0,        -- 已核销的付费次数；★只由核销/反结账变更，且必须与 card_consume_log 对应
  used_gift        INTEGER NOT NULL DEFAULT 0,        -- 已核销的赠送次数；扣减顺序由 store_config.gift_first 决定，默认先扣这项
  paid_amount_cent INTEGER NOT NULL DEFAULT 0,        -- 本卡实收金额，单位分；可能低于 card_type.price_cent（打折/抹零），售卡收入以本字段为准
  issued_on        TEXT    NOT NULL,                  -- 发卡日期 'yyyy-MM-dd'
  expire_on        TEXT    NOT NULL,                  -- 到期日 'yyyy-MM-dd'；延期时改这个字段并写 card_extend_log
  status           TEXT    NOT NULL DEFAULT 'ACTIVE', -- 卡状态：ACTIVE 可用 / EXPIRED 已过期（★余额不清零，可查可延期，只是不能核销）/ VOID 已作废（终态）
  source_bill_id   INTEGER,                           -- 售卡单 bill.id；反查「这笔钱是哪天收的」
  remark           TEXT,                              -- 备注
  created_at       TEXT    NOT NULL                   -- 创建时间
);
CREATE UNIQUE INDEX IF NOT EXISTS uk_card_no ON customer_card(card_no); -- 卡号唯一
CREATE INDEX IF NOT EXISTS idx_card_customer ON customer_card(customer_id, status); -- 客户详情页列卡、开单时筛可用卡
CREATE INDEX IF NOT EXISTS idx_card_expire ON customer_card(expire_on); -- 批量把到期卡置为 EXPIRED（定时任务用）


-- ============================================================================
-- 9. card_consume_log 卡核销流水
--    ★ 只允许 INSERT。反结账靠读这里的 from_gift 还原，不能靠当前开关重算。
-- ============================================================================
CREATE TABLE IF NOT EXISTS card_consume_log (
  id           INTEGER PRIMARY KEY AUTOINCREMENT, -- 主键，自增
  card_id      INTEGER NOT NULL REFERENCES customer_card(id), -- 被核销的卡
  bill_id      INTEGER NOT NULL,                  -- 核销发生在哪张销售单 bill.id（★不设外键，避免反结账删单时级联问题）
  bill_item_id INTEGER NOT NULL,                  -- 对应哪一行明细 bill_item.id；反结账按行精确还原次数
  qty          INTEGER NOT NULL DEFAULT 1,        -- 本次核销次数，当前固定 1；保留字段以支持将来一次核销多次
  from_gift    INTEGER NOT NULL DEFAULT 0,        -- ★本次扣的是哪一部分：1=赠送次数 0=付费次数。反结账必须按本字段还原，不能按当前 gift_first 开关重算（开关可能改过，重算会让 used_gift 变负数）
  operator     TEXT,                              -- 操作人
  created_at   TEXT    NOT NULL                   -- 核销时间
);
CREATE INDEX IF NOT EXISTS idx_consume_card ON card_consume_log(card_id, created_at); -- 查某张卡的完整使用历史（纠纷时出示）
CREATE INDEX IF NOT EXISTS idx_consume_bill ON card_consume_log(bill_id); -- 反结账时按单号捞本轮核销


-- ============================================================================
-- 10. card_extend_log 卡延期记录
--     ★ 延期等于单方面送钱给客户，必须留痕：谁改的、为什么、改前是几号。
-- ============================================================================
CREATE TABLE IF NOT EXISTS card_extend_log (
  id            INTEGER PRIMARY KEY AUTOINCREMENT, -- 主键，自增
  card_id       INTEGER NOT NULL REFERENCES customer_card(id), -- 被延期的卡
  old_expire_on TEXT    NOT NULL,                  -- 延期前的到期日
  new_expire_on TEXT    NOT NULL,                  -- 延期后的到期日（必须晚于旧值）
  reason        TEXT    NOT NULL,                  -- 延期原因，必填：客户投诉、疫情停业、员工失误补偿……这是唯一的追责凭证
  operator      TEXT    NOT NULL,                  -- 操作人（仅 ADMIN 有权限）
  created_at    TEXT    NOT NULL                   -- 操作时间
);


-- ============================================================================
-- 11. bill 单据
--     两种单共表：SALE 销售/服务单（有明细）、CARD 售卡收款单（无明细）。
-- ============================================================================
CREATE TABLE IF NOT EXISTS bill (
  id              INTEGER PRIMARY KEY AUTOINCREMENT, -- 主键，自增
  bill_no         TEXT    NOT NULL,                  -- 单号，唯一，人可读（前缀+营业日+当日序号）；客户报单号、打印小票都用它
  bill_type       TEXT    NOT NULL,                  -- 单据类型：SALE 销售/服务单 / CARD 售卡收款单（★售卡单不写 bill_item，金额直接从 received_cent 取）
  customer_id     INTEGER NOT NULL REFERENCES customer(id), -- 客户；售卡单也必须挂客户（否则卡没有主人）
  pet_id          INTEGER,                           -- 本次服务的主宠物；售卡单为空。混合单（一单多宠）以明细行的 pet_id 为准，此字段仅作默认值
  status          TEXT    NOT NULL DEFAULT 'OPEN',   -- 单据状态：OPEN 未结账 / SETTLED 已结账 / CANCELLED 已反结账（终态，需恢复请重开一单）
  total_cent      INTEGER NOT NULL DEFAULT 0,        -- 明细金额合计（优惠前），单位分
  discount_cent   INTEGER NOT NULL DEFAULT 0,        -- 整单优惠金额，单位分；分摊到明细的尾差归金额最大那一行
  receivable_cent INTEGER NOT NULL DEFAULT 0,        -- 应收 = total_cent - discount_cent
  received_cent   INTEGER NOT NULL DEFAULT 0,        -- 实收金额。★找零在系统外处理：现金收 100 应收 88，这里仍记 88，不记 100
  pay_method      TEXT,                              -- 收款方式：CASH 现金 / WECHAT 微信 / ALIPAY 支付宝 / BANK_CARD 银行卡 / OTHER 其他。★只做记账，不接任何支付通道。（刻意不用 'CARD' 以免与 bill_type 的 CARD 混淆）
  business_date   TEXT    NOT NULL,                  -- 营业日 'yyyy-MM-dd'：凌晨 04:00 前算前一天。★所有报表按本字段分组，不看 created_at
  settled_at      TEXT,                              -- 结账时间；未结账为 NULL
  cancelled_at    TEXT,                              -- 反结账时间；反结账后可查但不可再结
  cancel_reason   TEXT,                              -- 反结账原因，必填；这是对账时唯一能解释差异的字段
  request_id      TEXT,                              -- 提交幂等键，前端每次打开结账页生成一个 UUID；★重复提交撞唯一索引即拒绝，防止双击出两张单
  operator        TEXT,                              -- 开单人（员工显示名）
  remark          TEXT,                              -- 备注
  created_at      TEXT    NOT NULL                   -- 创建时间
);
CREATE UNIQUE INDEX IF NOT EXISTS uk_bill_no ON bill(bill_no); -- 单号唯一
CREATE UNIQUE INDEX IF NOT EXISTS uk_bill_request ON bill(request_id); -- 幂等键唯一：并发重复提交时由数据库兜底拦截
CREATE INDEX IF NOT EXISTS idx_bill_date ON bill(business_date, status); -- 日报/营业汇总按营业日+状态扫
CREATE INDEX IF NOT EXISTS idx_bill_customer ON bill(customer_id); -- 客户消费历史


-- ============================================================================
-- 12. bill_item 单据明细
--     ★ 只存快照，不存引用：名字、单价、金额在下单时冻结，之后改价改名都不回改历史单。
-- ============================================================================
CREATE TABLE IF NOT EXISTS bill_item (
  id              INTEGER PRIMARY KEY AUTOINCREMENT, -- 主键，自增
  bill_id         INTEGER NOT NULL REFERENCES bill(id), -- 所属单据
  item_type       TEXT    NOT NULL,                  -- 明细类型：SERVICE 服务 / PRODUCT 商品
  ref_id          INTEGER NOT NULL,                  -- 指向 service_item.id 或 product.id，按 item_type 解释（★不设外键：两个目标表共用一个字段）
  name_snapshot   TEXT    NOT NULL,                  -- 名称快照，必填；改名后历史单据不能跟着变，否则客户会说「我当时买的不是这个」
  size_tier       TEXT,                              -- 服务体型档：S / M / L / XL，决定用哪一档价；商品行为空
  pet_id          INTEGER,                           -- 本行服务的宠物；一单多宠必须按行记录，否则不知道钱花在谁身上
  qty             INTEGER NOT NULL DEFAULT 1,        -- 数量（服务次数 / 商品件数）
  unit_price_cent INTEGER NOT NULL DEFAULT 0,        -- 成交单价，单位分；已含体型档价与手工改价，不是挂牌价
  amount_cent     INTEGER NOT NULL DEFAULT 0,        -- 行金额 = unit_price_cent × qty（优惠前）
  discount_cent   INTEGER NOT NULL DEFAULT 0,        -- 分摊到本行的优惠金额；各行之和必须等于 bill.discount_cent
  paid_by_card    INTEGER NOT NULL DEFAULT 0,        -- 本行是否用次卡抵扣：1=是 0=否。★=1 时该行不计营业收入（钱在售卡当天已收过，再算一次会让当天营收虚高）
  card_id         INTEGER,                           -- 抵扣所用的 customer_card.id；paid_by_card=0 时为空
  sort_no         INTEGER NOT NULL DEFAULT 0         -- 打印/显示顺序
);
CREATE INDEX IF NOT EXISTS idx_item_bill ON bill_item(bill_id); -- 打开单据详情、反结账按单捞明细


-- ============================================================================
-- 13. store_config 门店参数
--     键值对，避免为几个开关改表结构。值统一存字符串，读取时再转换类型。
-- ============================================================================
CREATE TABLE IF NOT EXISTS store_config (
  k TEXT PRIMARY KEY,  -- 参数名，如 store_name（店名，打印在单据抬头）/ gift_first（true=核销先扣赠送次数）/ expire_warn_days（提醒提前天数，默认 30）/ low_stock_warn（低库存阈值，默认 3）
  v TEXT NOT NULL      -- 参数值，字符串形式；布尔用 'true'/'false'，数字直接写
);


-- ============================================================================
-- 14. sys_user 系统用户（店员）
--     ★ 管理员不写在 data.sql 里：BCrypt 哈希无法手工维护，改由 DataInitializer
--       在启动时判断 sys_user 为空再创建，否则会出现「哈希与编码器版本不匹配，密码永远不对」。
-- ============================================================================
CREATE TABLE IF NOT EXISTS sys_user (
  id            INTEGER PRIMARY KEY AUTOINCREMENT, -- 主键，自增
  username      TEXT    NOT NULL,                  -- 登录账号，唯一
  password_hash TEXT    NOT NULL,                  -- BCrypt 哈希（strength 10），★绝不存明文，也绝不回显
  display_name  TEXT    NOT NULL,                  -- 显示名，会写进单据的 operator 字段和操作日志
  role          TEXT    NOT NULL DEFAULT 'STAFF',  -- 角色：ADMIN 管理员（可作废卡、延期、反结账）/ STAFF 店员（只能开单结账核销）
  is_active     INTEGER NOT NULL DEFAULT 1,        -- 是否启用：1=可登录 0=已停用（离职不删账号，否则单据上的操作人就成了孤儿）
  created_at    TEXT    NOT NULL,                  -- 创建时间
  last_login_at TEXT                               -- 最近登录时间；长期未登录的账号可以回收权限
);
CREATE UNIQUE INDEX IF NOT EXISTS uk_sys_user ON sys_user(username); -- 账号唯一
```

#### 5.2.1 枚举取值字典

SQLite 没有 `ENUM` 类型，所有枚举都用 `TEXT` 存大写常量。下面这张表是**唯一权威定义**，代码里的常量类必须与它逐字一致（大小写敏感）。

| 表.字段 | 取值 | 含义 |
|---|---|---|
| `pet.species` | `DOG` / `CAT` / `OTHER` | 狗 / 猫 / 其他 |
| `pet.gender` | `MALE` / `FEMALE` / `UNKNOWN` | 公 / 母 / 未知 |
| `pet_event.event_type` | `VACCINE` / `RABIES` / `DEWORM` / `CHECKUP` | 疫苗 / 狂犬 / 驱虫 / 体检 |
| `pet_event.contact_status` | `NULL` / `CONTACTED` / `BOOKED` / `DONE` / `IGNORED` | 未处理 / 已联系 / 已预约 / 已完成 / 不再提醒 |
| `service_item` 体型档 | `S` / `M` / `L` / `XL` | ≤5kg / 5–15kg / 15–30kg / >30kg |
| `product_ledger.biz_type` | `IN` / `SALE` / `RETURN` / `CANCEL` / `ADJUST` | 采购入库 / 销售出库 / 退货入库 / 反结账回滚 / 盘点调整 |
| `product_ledger.ref_type` | `BILL` / `MANUAL` | 销售单 / 手工调整 |
| `customer_card.status` | `ACTIVE` / `EXPIRED` / `VOID` | 可用 / 已过期（余额不清零）/ 已作废（终态） |
| `bill.bill_type` | `SALE` / `CARD` | 销售服务单 / 售卡收款单 |
| `bill.status` | `OPEN` / `SETTLED` / `CANCELLED` | 未结账 / 已结账 / 已反结账（终态） |
| `bill.pay_method` | `CASH` / `WECHAT` / `ALIPAY` / `BANK_CARD` / `OTHER` | 现金 / 微信 / 支付宝 / 银行卡 / 其他 |
| `bill_item.item_type` | `SERVICE` / `PRODUCT` | 服务 / 商品 |
| `sys_user.role` | `ADMIN` / `STAFF` | 管理员 / 店员 |

**两处刻意的不一致，别当成笔误**：

- `bill.pay_method` 用 `BANK_CARD` 而不是 `CARD` —— 否则它和 `bill.bill_type = 'CARD'`（售卡单）在日志、报表里完全无法区分，排查问题时极易看错。
- `customer_card.status` 的 `EXPIRED` **不代表余额归零**。过期卡仍可查询余额、仍可延期恢复，只是不能核销。若把过期当成作废处理，客户会认为你把他的钱吞了。


### 5.3 初始化数据（`resources/schema/data.sql`）

```sql
INSERT OR IGNORE INTO store_config(k, v) VALUES
  ('store_name',      '宠物生活馆'),
  ('gift_first',      'true'),
  ('expire_warn_days','30'),
  ('low_stock_warn',  '3');
```

**管理员账号不写在 SQL 里**，因为 BCrypt 哈希无法手工维护。由 `DataInitializer` 在启动时检查：若 `sys_user` 为空 → 用 `BCryptPasswordEncoder.encode("123456")` 创建 `admin`，并打印一条日志提示改密码。

### 5.4 写库纪律（代码评审必查）

| # | 纪律 | 违反后果 |
|---|---|---|
| 1 | `card_consume_log` / `product_ledger` **只允许 INSERT** | 改流水 = 销毁证据，纠纷时无法自证 |
| 2 | 卡剩余次数**不存字段**，实时 `paid_qty - used_paid + gift_qty - used_gift` | 存了必然不同步 |
| 3 | 所有金额字段传 `int`，禁止 `double` / `float` | 浮点误差，一分一厘都对不上 |
| 4 | 库存变更与流水插入**同一事务** | 出现「改了库存没流水」 |
| 5 | `bill_item.name_snapshot` 必填 | 改名后历史单据全变样 |
| 6 | MyBatis 一律 `#{}`，禁止 `${}` | SQL 注入 |
| 7 | 删除一律逻辑删（`is_active=0` / `status='CANCELLED'`） | 单据与档案不可物理删除 |

## 6. 类型映射与工具类

### 6.1 日期 TypeHandler（必须自己写）

MyBatis 3.5 自带的 `LocalDateTimeTypeHandler` 按 `TIMESTAMP` 处理，SQLite 下行为不稳定。自定义两个：

```java
@MappedTypes(LocalDateTime.class)
public class LocalDateTimeTypeHandler extends BaseTypeHandler<LocalDateTime> {
    private static final DateTimeFormatter FMT =
            DateTimeFormatter.ofPattern("yyyy-MM-dd HH:mm:ss");

    @Override
    public void setNonNullParameter(PreparedStatement ps, int i,
                                    LocalDateTime p, JdbcType jdbcType) throws SQLException {
        ps.setString(i, p.format(FMT));
    }
    @Override
    public LocalDateTime getNullableResult(ResultSet rs, String column) throws SQLException {
        return parse(rs.getString(column));
    }
    @Override
    public LocalDateTime getNullableResult(ResultSet rs, int column) throws SQLException {
        return parse(rs.getString(column));
    }
    @Override
    public LocalDateTime getNullableResult(CallableStatement cs, int column) throws SQLException {
        return parse(cs.getString(column));
    }
    private LocalDateTime parse(String s) {
        if (s == null || s.trim().isEmpty()) return null;
        return LocalDateTime.parse(s, FMT);
    }
}
```

`LocalDateTypeHandler` 同理，格式 `yyyy-MM-dd`。通过 `mybatis.type-handlers-package` 自动注册。

**写入时必须显式给 LocalDateTime**，不要让数据库用 `datetime('now')` —— 数据库取的是 UTC，会和 Java 的本地时间差 8 小时。

### 6.2 Money 工具类

```java
public final class Money {
    private Money() {}

    /** 分 -> "128.00" */
    public static String yuan(int cent) {
        return BigDecimal.valueOf(cent, 2).toPlainString();
    }

    /** "128.5" -> 12850；非法输入抛 BizException */
    public static int toCent(String yuan) {

        }
    }

    /** 按比例分摊，尾差归最大项 */
    public static int[] allocate(int totalCent, int[] weights) { ... }
}
```

## 7. 关键流程详设

### 7.1 F1 售卡

```
输入：customerId, cardTypeId, receivedCent, payMethod
事务开始
  1. 校验客户存在且 is_active=1
  2. 校验卡类型存在且 is_active=1
  3. 计算 expire_on = 今天 + valid_days
  4. INSERT customer_card（card_no 见 §7.7，status='ACTIVE'）
  5. INSERT bill（bill_type='CARD', status='SETTLED',
                  total_cent = card_type.price_cent,
                  received_cent = 实收,
                  business_date = BusinessDate.of(now)）
  6. UPDATE customer_card SET source_bill_id = bill.id
事务提交
```

**售卡单不写 `bill_item`**。售卡收入直接取 `bill.received_cent` 汇总，不需要明细，少写一套逻辑就少一处出错。

### 7.2 F2 核销扣次（本系统最关键的 20 行 SQL）

必须用**一条带条件的 UPDATE** 完成「判余额 + 扣减」，不能先 SELECT 再 UPDATE（并发下会扣成负数）。

```sql
-- gift_first = true（默认）
UPDATE customer_card
SET used_gift = used_gift + CASE WHEN (gift_qty - used_gift) > 0 THEN 1 ELSE 0 END,
    used_paid = used_paid + CASE WHEN (gift_qty - used_gift) > 0 THEN 0 ELSE 1 END
WHERE id = #{cardId}
  AND status = 'ACTIVE'
  AND expire_on >= #{today}
  AND (paid_qty - used_paid + gift_qty - used_gift) > 0;
```

```sql
-- gift_first = false 时，把两处 CASE 条件换成 (paid_qty - used_paid) > 0 即可
```

**返回影响行数**：
- `1` → 成功，继续写 `card_consume_log`
- `0` → 用一条 SELECT 判断具体原因，抛对应错误码：
  ```sql
  SELECT status, expire_on,
         (paid_qty - used_paid + gift_qty - used_gift) AS remain
  FROM customer_card WHERE id = #{cardId}
  ```
  - `status='VOID'` → `CARD_VOID`
  - `status='EXPIRED'` 或 `expire_on < today` → `CARD_EXPIRED`
  - `remain <= 0` → `CARD_NO_BALANCE`
  - 查不到 → `CARD_NOT_FOUND`

**为什么不用乐观锁 version 字段**：`WHERE` 里的余额条件本身就是版本判断，语义更强（它保证的是「余额充足」，不是「没被别人改过」）。少一个字段，少一处漏更新的机会。

### 7.3 F3 库存扣减

```sql
UPDATE product
SET stock_qty = stock_qty - #{qty}
WHERE id = #{productId} AND stock_qty >= #{qty};
```

影响行数 `0` → 抛 `STOCK_NOT_ENOUGH`。成功后：

```sql
INSERT INTO product_ledger
  (product_id, biz_type, qty_change, before_qty, after_qty,
   ref_type, ref_id, operator, created_at)
VALUES
  (#{productId}, 'SALE', -#{qty}, #{beforeQty}, #{afterQty},
   'BILL', #{billId}, #{operator}, #{now});
```

`before_qty` / `after_qty` 在扣减后重新查询一次即可（同一事务内可见）。

### 7.4 F4 结账（主流程）

```
输入：customerId, petId, items[], discountCent, payMethod, requestId
事务开始
  1. 幂等：SELECT id, bill_no FROM bill WHERE request_id = #{requestId}
     若存在 → 直接返回该单，不重复处理
  2. 校验：items 非空；含 SERVICE 且 petId 为空 → PET_REQUIRED
  3. 计算每条明细 unit_price_cent：
     - PRODUCT：取 product.sale_price_cent
     - SERVICE：按 pet.weight_g 匹配体型档位取价（可被前端改档覆盖）
  4. total_cent = Σ(qty × unit_price_cent)
  5. 折扣分摊（§8.4）→ 每条 discount_cent、amount_cent = qty×单价 − discount
  6. receivable_cent = Σ(amount_cent)；若 discount > total → DISCOUNT_EXCEED_TOTAL
  7. INSERT bill（status='OPEN' 先占位，拿到 id）
  8. 遍历明细：
     a) 用卡抵扣 → 调 F2 扣次 → INSERT card_consume_log
                    → bill_item.amount_cent = 0, paid_by_card = 1
     b) 商品     → 调 F3 扣库存 → INSERT product_ledger
     c) INSERT bill_item（含 name_snapshot）
  9. UPDATE bill SET status='SETTLED', settled_at=now,
                    received_cent=实收, pay_method=?
事务提交
```

**为什么先插 bill 再插明细**：`card_consume_log.bill_item_id` 依赖明细 ID，而明细需要 `bill_id`。先拿主单 ID 是唯一顺序。

**`name_snapshot` 取值来源**：服务项目取 `service_item.name`，商品取 `product.name`，在插入明细那一刻读取，之后永不更新。

### 7.5 F5 反结账

```
事务开始
  1. 校验：当前用户 ADMIN；bill.status='SETTLED'；
           bill.business_date = BusinessDate.of(now)  → 否则 BILL_NOT_TODAY
  2. 读该单全部 card_consume_log，按 from_gift 还原：
     from_gift=1 → UPDATE customer_card SET used_gift = used_gift - 1
     from_gift=0 → UPDATE customer_card SET used_paid = used_paid - 1
     ★ 必须读日志，不能根据当前 gift_first 开关重算
  3. 读该单全部 PRODUCT 明细 → stock_qty 加回 → 写 biz_type='CANCEL' 的反向流水
  4. UPDATE bill SET status='CANCELLED', cancelled_at=now, cancel_reason=?
事务提交
```

**第 2 步是设计要点**：赠次优先开关可能在售卡后被改过。如果用当前开关推算「当时扣的是哪一类」，会出现 `used_gift` 变负数。**流水就是唯一真相**。

### 7.6 F6 到期提醒计算

```sql
SELECT e.id, e.next_due_on, e.event_type, e.contact_status,
       p.name AS pet_name, p.breed,
       c.name AS owner_name, c.phone
FROM pet_event e
JOIN pet p ON p.id = e.pet_id
JOIN customer c ON c.id = p.owner_id
WHERE e.next_due_on IS NOT NULL
  AND e.contact_status IS NULL
  AND e.next_due_on <= #{windowEnd}       -- today + N
  AND p.is_active = 1
ORDER BY e.next_due_on ASC;
```

`windowEnd` 由调用方传入：今日档 `today`、7 天档 `today+7`、30 天档 `today+30`。

逾期判断在 Java 层做：`nextDueOn.isBefore(today)` → 显示「已逾期 X 天」。**逾期项不筛掉**，它们在 SQL 里天然满足 `<= today`。

### 7.7 业务单号生成

```java
// 卡号：C + yyyyMMdd + 4 位序号，如 C202610230001
// 单号：S + yyyyMMdd + 4 位序号（售卡单 Z 开头），如 S202610230001
```

实现：单机场景直接用「当天已生成数量 + 1」，在事务内 `SELECT COUNT(*)+1`，配合 `card_no` 唯一索引兜底。并发极低（一天一单），不必上分布式 ID。

若插入时撞唯一索引（`SQLITE_CONSTRAINT_UNIQUE`），重试一次即可。

## 8. 核心算法

### 8.1 体型档位匹配

| 档位 | 体重区间 | 说明 |
|---|---|---|
| S | `weight_g < 10000` | < 10kg |
| M | `10000 ≤ w < 25000` | 10–25kg |
| L | `25000 ≤ w < 40000` | 25–40kg |
| XL | `w ≥ 40000` | > 40kg |

**边界取大档**（左闭右开）。`weight_g` 为空时默认 S，并在界面提示「未录体重，按小型计价」。

### 8.2 年龄显示

```java
if (birthday == null) return "—";
Period p = Period.between(birthday, today);
if (p.isNegative()) return "—";
if (p.getYears() > 0) return p.getYears() + "岁" + p.getMonths() + "个月";
return p.getMonths() + "个月";
```

### 8.3 次卡到期日

`expire_on = issued_on + valid_days`，用 `LocalDate.plusDays`，不用自然月（避免「1 月 31 日 + 1 个月」的歧义）。

### 8.4 折扣分摊（写死，不许改）

```java
public static int[] allocate(int totalDiscount, int[] baseAmounts) {
    int n = baseAmounts.length;
    int[] result = new int[n];
    long base = 0;
    for (int a : baseAmounts) base += a;
    if (base <= 0) return result;

    int allocated = 0;
    for (int i = 0; i < n; i++) {
        // 用 long 计算，避免 int 溢出；四舍五入到分
        result[i] = (int) Math.round((double) totalDiscount * baseAmounts[i] / base);
        allocated += result[i];
    }

    // 尾差归金额最大的明细
    int diff = totalDiscount - allocated;
    if (diff != 0) {
        int maxIdx = 0;
        for (int i = 1; i < n; i++) {
            if (baseAmounts[i] > baseAmounts[maxIdx]) maxIdx = i;
        }
        result[maxIdx] += diff;
    }
    return result;
}
```

**必写单测**：`totalDiscount=1000`（10 元）、三条明细 `[3333, 3333, 3334]`，断言 `Σresult == 1000` 且三者互差不超过 1 分。

`baseAmounts` 是「不参与分摊」的过滤后的数组 —— 用次卡抵扣的明细已记 0，不参与基数计算。

### 8.5 三类收入口径（报表 SQL）

```sql
-- 单日营业汇总
SELECT
  (SELECT IFNULL(SUM(received_cent),0) FROM bill
    WHERE bill_type='CARD' AND status='SETTLED'
      AND business_date = #{date})                      AS card_income_cent,
  (SELECT IFNULL(SUM(i.amount_cent),0) FROM bill_item i
    JOIN bill b ON b.id=i.bill_id
    WHERE b.bill_type='SALE' AND b.status='SETTLED'
      AND b.business_date = #{date}
      AND i.item_type='PRODUCT' AND i.paid_by_card=0)   AS product_income_cent,
  (SELECT IFNULL(SUM(i.amount_cent),0) FROM bill_item i
    JOIN bill b ON b.id=i.bill_id
    WHERE b.bill_type='SALE' AND b.status='SETTLED'
      AND b.business_date = #{date}
      AND i.item_type='SERVICE' AND i.paid_by_card=0)   AS service_income_cent,
  (SELECT COUNT(*) FROM bill
    WHERE bill_type='SALE' AND status='SETTLED'
      AND business_date = #{date})                      AS bill_count,
  (SELECT IFNULL(SUM(qty),0) FROM card_consume_log l
    WHERE substr(l.created_at,1,10) = #{date})          AS consume_times;
```

**验收要点**：三列之和必须等于当日实收总额。若不等，先查是不是有 `paid_by_card=1` 但 `amount_cent ≠ 0` 的脏数据。

## 9. 并发与事务控制

### 9.1 SQLite 并发模型与对策

| 问题 | 对策 |
|---|---|
| 同时两个线程写 → `SQLITE_BUSY` | `busy_timeout=5000` 让第二个等 5 秒；单店场景等不到 5 秒就完事了 |
| 连接池太多抢锁 | `maximum-pool-size=4` |
| 长事务持锁 | 结账事务控制在 200ms 内；**禁止在事务里做网络请求、文件 IO、`sleep`** |
| 脏读 | 不用 MyBatis 二级缓存（`cache-enabled: false`） |

### 9.2 事务注解规范

```java
@Transactional(rollbackFor = Exception.class)
public Result settle(BillForm form) { ... }
```

- **必须写 `rollbackFor = Exception.class`**：Spring 默认只回滚 `RuntimeException`，而 `BizException` 若继承 `Exception` 就不会回滚
- 建议 `BizException extends RuntimeException`，双保险
- 查询方法加 `@Transactional(readOnly = true)`，减少写锁申请

### 9.3 表单重复提交

| 层 | 做法 |
|---|---|
| 前端 | 提交后按钮置灰 + `disabled` |
| 后端 | 表单带隐藏字段 `requestId`（UUID），`bill.request_id` 建**唯一索引** |
| 兜底 | 插入撞唯一索引 → 查出已有单直接返回，不报错 |

**唯一索引是最终防线**，前端置灰只是体验优化。

服务端**必须重算一遍金额**，不信任前端传的 `amount`。前端算的是体验，后端算的才是账。

## 12. 安全设计

### 12.1 登录与会话

```
POST /login {username, password}
  → 查 sys_user（is_active=1）
  → BCryptPasswordEncoder.matches(raw, hash)
  → 成功：session 存 SessionUser{id, username, displayName, role}
  → 失败：统一提示"用户名或密码错误"（不区分哪个错）
```

| 项 | 配置 |
|---|---|
| 密码算法 | BCrypt，strength 10 |
| 会话超时 | 8 小时 |
| 并发会话 | 允许（单店同一个人可能用两台电脑） |
| 登出 | `session.invalidate()` |

**为什么不用 Spring Security**：本版只需「登录 + 两个角色」，引入全家桶要多写 100 行配置、多踩 3 个坑（CSRF、默认登录页、`AuthenticationManager` 装配）。**只引 `spring-security-crypto`**，拿到 `BCryptPasswordEncoder` 就够。

### 12.2 拦截器

```java
// LoginInterceptor：拦所有路径，放行 /login /css /js /vendor /error
// AdminInterceptor：拦 /system/**、/cards/*/void、/cards/*/extend、/bills/*/cancel
```

`AdminInterceptor` 里判断 `SessionUser.role`，非 `ADMIN` 抛 `BizException(NO_PERMISSION)`。

### 12.3 校验双层

| 层 | 做什么 | 举例 |
|---|---|---|
| 前端 | `required` / `maxlength` / Alpine 即时提示 | 手机号 11 位 |
| 后端 | Bean Validation `@NotBlank` `@Pattern` + 业务校验 | 手机号唯一、卡余额充足 |

**后端校验不可省略**，前端只是体验。每条 `@Valid` 失败要转成中文提示。

## 13. 部署与启动

### 13.1 start.bat

> 编码：保存为 **UTF-8 无 BOM**（若出现中文乱码，改用 ANSI/GBK 保存并删除 `chcp` 行）。

```bat
@echo off
setlocal
chcp 65001 >nul
title 宠物店管理系统
cd /d "%~dp0"

set "APP_HOME=%~dp0"
set "JAR=%APP_HOME%pet-shop.jar"

if not exist "%JAR%" (
  echo [错误] 未找到 pet-shop.jar，请确认它与 start.bat 在同一目录。
  pause
  exit /b 1
)

set "JAVA_CMD=java"
if exist "%APP_HOME%jre\bin\java.exe" set "JAVA_CMD=%APP_HOME%jre\bin\java.exe"

"%JAVA_CMD%" -version >nul 2>&1
if errorlevel 1 (
  echo [错误] 未检测到 Java 运行环境。
  echo 请安装 JDK/JRE 1.8，或把 jre 文件夹放到本目录下。
  pause
  exit /b 1
)

if not exist "%APP_HOME%logs" mkdir "%APP_HOME%logs"
if not exist "%APP_HOME%data" mkdir "%APP_HOME%data"
if not exist "%APP_HOME%data\backup" mkdir "%APP_HOME%data\backup"

echo ============================================
echo   宠物店管理系统 正在启动，请稍候...
echo   启动后会自动打开浏览器
echo   关闭此窗口即停止程序
echo ============================================
echo.

rem 8 秒后自动打开浏览器（与下面的前台进程并行）
start "" cmd /c "timeout /t 8 >nul & start http://localhost:8080"

"%JAVA_CMD%" -Dfile.encoding=UTF-8 -Duser.timezone=Asia/Shanghai ^
  -jar "%JAR%" ^
  --spring.config.additional-location=file:./config/

echo.
echo 程序已退出。若启动失败，请查看 logs\error.log
pause
```

**四个不显眼但必须有的细节**：

| 细节 | 不写会怎样 |
|---|---|
| `cd /d "%~dp0"` | 从桌面快捷方式启动时工作目录是 `C:\Windows\System32`，数据库写不进去 |
| `-Dfile.encoding=UTF-8` | Windows 中文环境下日志与界面出现乱码 |
| `-Duser.timezone=Asia/Shanghai` | 营业日算错（服务器时区不同） |
| `start "" cmd /c "timeout ... & start url"` | 直接 `start url` 会在服务启动前打开，白页 8 秒 |

### 13.2 start.sh / stop.sh

```bash
#!/bin/bash
APP_HOME=$(cd "$(dirname "$0")" && pwd)
cd "$APP_HOME"
mkdir -p logs data/backup

JAVA_CMD=java
if [ -x "$APP_HOME/jre/bin/java" ]; then
  JAVA_CMD="$APP_HOME/jre/bin/java"
fi

if ! "$JAVA_CMD" -version >/dev/null 2>&1; then
  echo "[错误] 未检测到 Java，请安装 JDK/JRE 1.8"
  exit 1
fi

nohup "$JAVA_CMD" -Dfile.encoding=UTF-8 -Duser.timezone=Asia/Shanghai \
  -jar pet-shop.jar \
  --spring.config.additional-location=file:./config/ \
  > logs/console.log 2>&1 &

echo $! > app.pid

echo "访问 http://localhost:8080   日志 logs/console.log"
```


### 13.4 备份

```java
@Component
public class BackupTask {
    @Scheduled(cron = "0 0 3 * * ?")
    public void dailyBackup() {
        String name = "pet-" + LocalDateTime.now()
                .format(DateTimeFormatter.ofPattern("yyyyMMdd-HHmm")) + ".db";
        Path target = Paths.get(config.getBackupDir(), name);
        // VACUUM INTO 生成一致性快照，比直接拷文件安全
        jdbcTemplate.execute("VACUUM INTO '" + target.toString().replace("\\", "/") + "'");
        cleanOldBackups(config.getBackupKeep());
    }
}
```

**为什么用 `VACUUM INTO` 而不是复制文件**：直接拷 `.db` 时如果正好有事务在写，拷到的是半个事务。`VACUUM INTO` 会生成一份完整且一致的快照，还能顺带压缩（碎片整理）。

保留策略：最近 7 份 + 每月 1 号那份长期保留。
