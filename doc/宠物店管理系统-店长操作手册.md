# 宠物店管理系统 · 店长操作手册

> 适用角色：店长（管理员 ADMIN）  
> 适用版本：当前单店版  
> 使用目的：指导店长完成每日营业、客户与宠物管理、次卡管理、寄养预约、库存维护、营业对账及数据安全管理。

---

## 一、使用前须知

### 1. 登录系统

1. 打开浏览器，访问系统地址，默认本机地址为 `http://localhost:8080`。
2. 输入管理员账号和密码，点击“登录”。
3. 首次部署的默认账号为 `admin / 123456`。正式使用前必须修改默认密码，不要多人共用店长账号。
4. 连续输错密码 5 次，账号会暂时锁定 10 分钟。
5. 登录会话最长约 8 小时，页面跳转登录页后重新登录即可。
6. 使用完毕点击页面右上角“退出”。公用电脑不要保存密码，也不要直接关闭浏览器代替退出。

> 当前没有“修改本人密码”的独立入口。店长可在“系统 → 用户管理”中找到自己的账号，点击“重置密码”，设置至少 6 位的新密码。

### 2. 店长的主要权限

店长除日常开单、客户档案、寄养、预约和提醒外，还负责：

- 售卡、卡类型维护、次卡延期和作废；
- 商品、服务和笼位配置；
- 商品入库及库存调整；
- 当日异常单据反结账；
- 用户、门店参数、数据备份与恢复；
- 审计查询和数据体检。

店员没有上述管理权限。不要把自己的管理员账号借给店员操作。

### 3. 重要业务口径

- 系统只记录现金、微信、支付宝、银行卡或其他收款方式，**不会真的发起微信或支付宝扣款**。收款以门店实际到账为准。
- 营业日凌晨 4 点切换：00:00–03:59 的营业数据默认归入前一营业日。
- 商品、服务、寄养和售卡金额均以结账时系统保存的数据为准，打印或查询历史单据不会受后续价目调整影响。
- 系统不提供储值余额和退款流程。需要退款时，应按门店线下制度处理并留存凭证。

## 二、店长每日工作清单

### 1. 开始营业

1. 打开“首页看板”，检查今日单量、今日预约、在店寄养、待提醒、临期商品和低库存。
2. 打开“预约看板”，确认当日到店安排。
3. 打开“寄养看板”，检查：
   - 今日应入住；
   - 今日或已超期应离店；
   - 当前在住宠物及超期标红记录。
4. 打开“到期提醒”，安排当日客户联系。
5. 检查“商品库存”，对低库存、临期商品及时补货或处理。

### 2. 营业过程中

- 新客户先建档，再添加宠物，最后开单或售卡。
- 服务开单前核对宠物和体重，确认系统选用的体型价格档。
- 使用次卡时，核对卡号、剩余次数、有效期及适用服务。
- 寄养入住前检查有效疫苗或狂犬记录。
- 每日填写在住宠物的喂养和异常记录。
- 收款、折扣、改价、库存调整等操作由当班人员复核。

### 3. 结束营业

1. 检查当日预约是否仍有未处理的“已预约”或“已到店”记录。
2. 检查寄养是否仍有应入住、应退住未处理记录。
3. 打开“日营业汇总”，核对售卡、商品、服务及寄养收入、实收合计和单量。
4. 将系统实收与现金、微信、支付宝、银行卡实际到账逐笔核对。
5. 对差异先查单据状态和收款方式，不要直接用手工库存调整或反结账“凑数”。
6. 重要营业日或大量数据变更后，可在“系统 → 数据备份”执行一次手动备份。

## 四、客户与宠物档案

### 1. 新建客户

1. 进入“前台 → 客户档案”。
2. 先按姓名或手机号搜索，避免重复建档。
3. 点击“客户建档”。
4. 填写姓名或称呼、11 位手机号，可按需填写来源渠道和备注。
5. 保存后进入客户详情。

手机号是客户的唯一标识，重复手机号不能再次建档。客户只能停用或恢复，不能物理删除；历史单据、次卡和宠物档案都会保留。

### 2. 添加或维护宠物

1. 在客户详情找到“宠物”区域，点击添加。
2. 填写昵称、种类、品种、性别等资料。
3. 重点核对生日、体重、习性及禁忌。
4. 保存后，该宠物即可用于开单、预约和寄养。
5. 需要修改时，在客户详情点击对应宠物的编辑入口。

服务价格按体重分档：

| 体重 | 价格档 |
|---|---|
| 未填体重或小于 10 kg | S |
| 10 kg 至小于 25 kg | M |
| 25 kg 至小于 40 kg | L |
| 40 kg 及以上 | XL |

> 体重会直接影响服务价格。宠物体重明显变化后，应先更新档案再开单。

### 3. 停用与恢复

- 停用客户或宠物后，不再出现在正常的新业务选择列表中。
- 停用不会删除历史数据。
- 默认客户列表不显示已停用客户，需要时勾选“显示已停用”。
- 恢复后，可重新办理正常业务。

## 五、开单收银、单据查询与反结账

### 1. 标准开单流程

1. 进入“前台 → 开单收银”，搜索并选择客户。
2. 选择本次服务对应的宠物。
3. 添加服务项目或商品：
   - 点击服务项目加入明细；
   - 点击商品加入明细；
   - 商品也可扫码，或输入条码后回车。
4. 核对每条明细：
   - 服务是否选对宠物；
   - 体型档和价格是否正确；
   - 商品数量是否正确；
   - 是否需要删除或重新添加。
5. 服务使用次卡时，在该服务行选择对应次卡；不使用则保持“收现金”。
6. 如需优惠，填写整单折扣，并确认优惠原因符合门店制度。
7. 选择实际收款方式，填写必要备注。
8. 核对明细合计、次卡抵扣和最终应收。
9. 点击“提交结账”，成功后进入单据详情。
10. 需要纸质单据时，使用详情页的浏览器打印功能。

### 2. 次卡抵扣注意事项

- 只有当前客户持有、仍有效、次数充足且适用于该服务的卡才可选择。
- 次卡抵扣行的金额为 0，不会重复计算服务收入。
- **每条次卡抵扣明细数量必须为 1。**同一服务需要扣多次时，应拆成多条服务明细，每条分别核销 1 次。
- 默认先扣赠送次数，再扣付费次数；可在“门店参数”调整扣次顺序。
- 重复点击提交不要作为重试习惯。若页面无响应，先到“单据查询”确认是否已经生成单据。

### 3. 查询和打印单据

1. 进入“前台 → 单据查询”。
2. 可按营业日起止日期、单据状态、宠物、单号、客户或手机号查询。
3. 点击单号或“详情”查看明细、金额、收款方式及反结账信息。
4. 使用筛选后如需翻页，应重新核对筛选条件是否仍然生效。

### 4. 反结账

仅用于纠正**当前营业日、已结账的普通销售单**。

操作步骤：

1. 在“单据查询”找到原单，核对单号、客户和金额。
2. 进入详情，点击“反结账”。
3. 填写清楚、可追溯的原因。
4. 确认后重新核对库存、次卡和报表。

反结账成功后：

- 原销售出库按批次退回库存；
- 已扣次卡按原付费或赠次类型返还；
- 原单不再计入已结账收入；
- 相关提成以负数记录冲销，不删除原记录。

> **高风险：反结账不是通用撤销。**售卡收款单不能反结账；跨营业日单据不能反结账；预约来源单不会自动恢复为“已到店”；寄养结算单也不会自动恢复为“在住”。涉及预约或寄养时，必须先确认后续业务如何处理。

## 六、次卡管理

### 1. 新增卡类型

1. 进入“会员卡 → 卡类型”。
2. 填写卡名称、付费次数、赠送次数、售价和有效天数。
3. 选择适用服务；不选表示不限服务。
4. 核对后保存。

卡类型可停售或重新上架。当前页面不能编辑已有卡类型，因此新增前必须核对次数、价格、有效期和适用范围。已售出的卡保留售卡时的配置，不随后续卡类型变化。

### 2. 售卡

1. 进入“会员卡 → 售卡”，或从客户详情进入售卡。
2. 选择客户和仍在售的卡类型。
3. 核对页面带出的标准售价；如有优惠，按门店审批结果填写实收金额。
4. 选择实际收款方式。
5. 确认客户、卡类型、次数和实收金额后，点击“确认售卡”。
6. 到“次卡余额表”或客户详情核对新卡，并到“单据查询”核对售卡收款单。

> 售卡会同时生成客户次卡和售卡收款单。售卡单不能反结账，系统也没有售卡退款流程；不要重复点击“确认售卡”。

### 3. 查询次卡

进入“会员卡 → 次卡余额表”：

- 按客户名、手机号或卡号搜索；
- 按可用、已过期、已作废筛选；
- 查看总次数、已用次数、剩余次数和到期日；
- 点击卡号进入详情，查看收款单、核销流水和延期记录。

实际能否核销还受到期日影响，不要只看“可用”标签。

### 4. 延期

1. 进入卡详情，找到“延期”。
2. 选择新的到期日，必须晚于当前到期日。
3. 填写延期原因并确认。
4. 在延期记录中核对结果。

已作废卡不能延期。

### 5. 作废

1. 进入卡详情，点击“作废”。
2. 已发生核销的卡必须填写作废原因；建议所有作废都填写原因。
3. 与客户确认剩余次数、线下退款或补偿方案后再操作。

> **作废后不能核销、不能延期，页面没有恢复功能；作废不等于退款，也不会撤销售卡收款单。**

## 七、预约管理

### 1. 新建预约

1. 进入“寄养·预约 → 新建预约”。
2. 选择客户，再选择该客户名下的宠物。
3. 选择服务项目、预约日期和时段。
4. 填写备注并保存。

预约日期不能早于今天。系统按每 30 分钟一个时段安排，满员后不能继续预约。宠物必须处于在册状态。

> 正在寄养的宠物需要额外确认才能建立到店预约。当前页面对这类宠物的确认提示可能无法正常显示，建议先核对寄养安排，避免重复预约。

### 2. 到店、转开单和完成

1. 打开“预约看板”，默认显示今天，也可切换日期。
2. 客户到店后，在对应预约点击“到店”。
3. 点击“转开单”，系统会预填预约宠物和服务。
4. 核对价格档、次卡、其他商品服务及折扣。
5. 完成结账后，预约自动变为“已完成”，并关联账单。

只有“已到店”的预约可以转开单。预约项目的开单明细仍可修改，结账前必须复核。

### 3. 取消和未到

- 尚未到店的预约可点击“取消”。
- 历史逾期未处理记录可标记“未到”。
- 已取消或未到不等于生成任何账单。
- 预约完成后的账单反结账，不会把预约恢复为“已到店”。

## 八、寄养管理

### 1. 配置笼位

进入“寄养·预约 → 笼位管理”，可新增、编辑、停用或启用笼位。

重点字段：

- 唯一编号，如 `R01`；
- 适用类型：S、M、L、XL、CAT；
- 每晚价格；
- 位置说明。

系统不会强制校验宠物体型或物种是否与笼位类型一致，店长应人工核对。仍有宠物在住时，不要直接停用笼位。

### 2. 新建寄养单

1. 进入“寄养·预约 → 新建寄养”。
2. 先选择客户，再选择宠物。
3. 选择启用中的笼位。
4. 填写计划入住时间和预离店日。
5. 核对系统带出的每晚价，可按审批结果调整。
6. 填写押金及特殊照护要求。
7. 保存后，寄养单状态为“待入住”。

预离店日必须晚于入住日。同一笼位的待入住或在住订单不能时间重叠。建单时疫苗异常可能只作预警，正式入住时会强制检查。

未入住前如笼位、价格等填错，通常应取消寄养单后重新建立。

### 3. 办理入住

1. 在寄养看板的“今日应入住”或寄养详情中打开订单。
2. 核对宠物、笼位、实际到店情况和特殊照护要求。
3. 确认疫苗或狂犬记录有效。
4. 点击“办理入住”。

没有疫苗/狂犬记录，或记录已过期，系统会拒绝入住。补录方法见“到期提醒与免疫记录”。入住成功后，实际入住时间更新为操作当时时间。

### 4. 每日喂养记录

1. 打开在住寄养单详情。
2. 在“每日记录”选择日期，默认今天。
3. 填写喂食次数、是否遛弯、精神、大便及异常情况。
4. 点击保存。

每个寄养单每天只能保存一条记录，日期不能早于入住日。录错后页面不能直接修改，因此保存前要核对日期和内容；不要填写未来日期。

### 5. 修改预离店日

1. 在在住寄养单详情找到“预离店日改为”。
2. 选择新日期并填写客户加住等原因。
3. 点击“改期”。

系统会重新检查笼位冲突，修改原因会追加到寄养备注中。

### 6. 退住结算

1. 在寄养看板或详情点击“退住结算”。
2. 核对实际入住日、当天退住日、每晚价和预计晚数。
3. 选择实际收款方式。
4. 确认后退住，系统自动生成销售单并跳转到单据详情。
5. 核对结算单金额及实际到账。

计费规则：

- 按实际入住日期至实际退住日期的自然日晚数计算；
- 最少按 1 晚；
- 金额＝实际晚数 × 每晚价；
- **押金只做记录，不会自动从退住结算金额中扣除，也没有自动退押金流程。**

退住后不能重复退住。对寄养结算单反结账，不会把宠物恢复为“在住”。

### 7. 历史寄养查询

“寄养看板”底部的“历史寄养单”支持按单号、客户、手机号、宠物名和日期范围查询。未手动选择日期时，默认查询本月 1 日至本月最后一天。

## 九、到期提醒与免疫记录

### 1. 补录疫苗、驱虫或体检

1. 进入“客户档案”，打开客户详情。
2. 点击“记一针”。
3. 选择宠物和记录类型：疫苗、狂犬、体内驱虫、体外驱虫或体检。
4. 填写实际发生日期。
5. 填写下次到期日；留空时系统自动推算：
   - 疫苗、狂犬：发生日期 +365 天；
   - 体内驱虫：+90 天；
   - 体外驱虫：+30 天；
   - 体检：+365 天。
6. 按需填写医院、机构、批号、品牌和不良反应等备注。
7. 保存后重新检查寄养入住或提醒结果。

下次到期日不能早于发生日期。自动推算日期如与疫苗本或医嘱不一致，应手工填写正确到期日。

### 2. 跟进提醒

“到期提醒”提供全部未处理、今日、7 天内和 30 天内清单。

可执行：

- 点击电话号码，由当前设备发起拨号；
- 复制手机号；
- 标记已联系；
- 标记已预约；
- 标记已完成；
- 标记暂不联系。

> 标记后，该记录会从待处理清单移出，页面没有撤销标记按钮。“已预约”不会自动创建预约单，“已完成”也不会自动生成新的免疫记录；实际业务仍需分别办理。系统不会自动发送短信或微信。

## 十、商品库存与服务项目

### 1. 新建商品

1. 进入“经营 → 商品库存”，点击“新增商品”。
2. 填写商品名称和规格、条码、售价、成本价、安全库存及商品有效期。
3. 保存后，新商品初始库存为 0。
4. 返回商品列表，通过“入库”增加实际库存。

条码用于扫码开单，应避免重复或录入错误。成本价影响商品毛利统计，老数据成本为 0 时毛利会偏高。

### 2. 入库与库存调整

快速入库：

1. 在商品列表找到商品，点击“入库”。
2. 填写实际到货数量。
3. 核对后保存，再检查库存和流水。

其他调整：

1. 进入商品的“流水”页面。
2. 按实际业务选择采购入库、退货入库或盘点调整。
3. 盘盈填正数，盘亏填负数。
4. 建议每次都填写真实原因和依据。
5. 保存后核对商品结存及新增流水。

注意事项：

- 变动数量不能为 0；库存不足时不能继续负向调整。
- 库存流水只能追加和查询，不能修改或删除。
- 不要用“盘点调整”代替正常销售、采购或报损。
- 负向手工调整可能造成总库存与批次结存不一致，操作后应通过“数据体检”复查。

### 3. 低库存与有效期

- 商品安全库存为 0 时，使用“门店参数”中的全局低库存阈值。
- 库存小于或等于阈值即属于低库存。
- 商品页面临期提醒主要按商品级有效期检查未来 30 天。
- 修改全局阈值后，部分列表行内“低”标识可能与筛选口径不一致，应以实际库存和商品安全库存共同复核。

### 4. 商品停售与编辑

- 停售后不再用于正常新开单，历史单据保留。
- 编辑已停售商品并保存，可能同时使其重新上架；保存后应核对商品状态。
- 不能直接编辑库存数字，必须通过入库或库存调整留下流水。

### 5. 服务项目

1. 进入“经营 → 服务项目”。
2. 新增时填写服务名称、耗时、S/M/L/XL 四档价格和排序号。
3. 保存后可用于开单、预约及卡类型适用范围配置。
4. 不再提供的服务可下架，需要时重新上架。

当前页面不能编辑已有服务项目，新增前应核对名称、耗时和各档价格。下架不影响历史单据。

## 十一、营业报表与对账

### 1. 日营业汇总

进入“经营 → 日营业汇总”，默认查询当前营业日，也可选择其他日期。

主要指标：

- 售卡收入；
- 商品收入；
- 服务收入，包含寄养结算；
- 实收合计；
- 销售单量，不含售卡单；
- 次卡核销次数。

对账时只统计已结账单据，已反结账单据不计入。次卡抵扣服务不再计算服务收入，售卡在售卡当日确认收入。

### 2. 月度汇总

进入“经营 → 月度汇总”，选择月份后查看每日汇总和月度合计。

“商品毛利”＝商品收入－销售出库批次成本，**不是扣除房租、人工、水电等费用后的全店利润**。历史商品成本缺失或为 0 时，毛利会虚高。

### 3. 推荐对账顺序

1. 先确认查询营业日是否正确。
2. 分别核对售卡收入和普通销售单收入。
3. 按现金、微信、支付宝、银行卡及其他方式核对实际到账。
4. 检查是否有已反结账单据及其原因。
5. 检查次卡抵扣，避免把抵扣金额当作现金收入。
6. 检查寄养结算是否已计入服务收入。
7. 仍有差异时，进入单据查询逐单核对，不要直接修改库存或补一张无实际业务的单据。

## 十二、用户与门店参数

### 1. 用户管理

进入“系统 → 用户管理”，可以：

- 新增店员或管理员；
- 修改显示名；
- 停用或启用账号；
- 重置密码；
- 删除店员账号。

管理要求：

- 每人使用独立账号，按岗位分配角色。
- 登录名创建后不能在页面修改，密码至少 6 位。
- 不能停用自己，也不能把自己降为店员。
- 系统至少保留一个启用中的管理员。
- 管理员不能删除，只能停用。
- **删除店员账号不可恢复，操作前必须确认。**
- 员工离职、停用或角色变化后，应要求其退出并重新登录；必要时联系技术人员重启服务，确保旧会话失效。

### 2. 门店参数

进入“系统 → 门店参数”：

| 参数 | 用途 |
|---|---|
| 店名 | 页面标题、单据抬头等 |
| 赠次优先 | 开启后次卡先扣赠送次数，关闭后先扣付费次数 |
| 低库存阈值 | 商品安全库存为 0 时使用的默认值 |
| 提醒提前天数 | 当前仅保存和回显，固定提醒档位及首页统计不随其变化 |

修改扣次顺序会影响之后的核销，不会重算历史核销流水。变更前应告知收银人员。

## 十三、备份、恢复、审计与数据体检

### 1. 数据备份

系统数据库位于运行目录的 `data/pet.db`，备份位于 `data/backup/`。

- 每天 03:00 自动备份，但系统当时必须正在运行。
- 默认保留最近 7 份，并保留每月 1 日生成的备份。
- 进入“系统 → 数据备份”，点击“立即手动备份”可立即生成一份。
- 页面显示备份文件名，不提供下载按钮。

> 备份保存在同一台电脑上，不能防止硬盘损坏或整机丢失。应让技术人员定期把备份复制到另一台电脑、移动硬盘或安全的网络存储。

建议手动备份时机：大量资料导入后、集中库存调整后、重要版本升级前、恢复数据前。

### 2. 备份恢复

恢复会用旧备份**整库替换当前数据**，不是合并。恢复时点之后新增或修改的数据都会被覆盖。

标准步骤：

1. 停止全店开单、售卡、寄养、库存等所有业务操作。
2. 确认要恢复的备份日期和文件，必要时先手动备份当前数据。
3. 进入“系统 → 备份恢复”。
4. 选择已有备份，或上传 `.db` 文件；同时提供时，上传文件优先。
5. 点击“校验并准备恢复”，确认风险提示。
6. 系统校验数据库完整性、必需表和可用管理员账号，并自动备份当前库。
7. 校验通过后系统进入维护模式，此时不要继续办理业务。
8. 由店长或技术人员关闭并重新启动系统，启动时才会真正替换数据库。
9. 重新登录后，抽查客户、商品、单据和次卡，确认恢复的是正确时点。

如尚未重启，可在“备份恢复”或维护页取消恢复，继续使用当前数据库。重启完成替换后，不能再靠“取消准备”回滚，只能使用恢复前自动保存的备份再执行一次恢复。

上传文件必须为 `.db`，单文件最大 100 MB。恢复属于高风险操作，建议由店长和技术人员共同完成。

### 3. 审计日志

进入“系统 → 审计日志”，可按操作类型、操作人和起止日期查询，查看操作时间、对象、操作人、IP 及变更摘要。

当前审计主要覆盖供应商、采购、批次、盘点、提成和恢复准备等动作，**并非所有业务操作都有审计记录**。卡延期应查看卡详情的延期流水，反结账原因应查看原单据。

### 4. 数据体检

1. 进入“系统 → 数据体检”。
2. 点击“重新检查”。
3. 逐项查看商品库存、批次、优惠分摊、卡核销、寄养结算和提成检查结果。
4. 出现异常时，先备份，再结合原单据和流水排查。

数据体检只读，不会自动调账或修复。即使顶部显示“全部通过”，也应逐项确认没有单独显示“检查失败”的项目。

## 十四、常见问题处理

| 现象 | 处理方法 |
|---|---|
| 忘记密码或密码输错被锁定 | 锁定 10 分钟后再试，或由其他管理员在“用户管理”重置密码 |
| 店员看不到售卡、卡类型等菜单 | 这些属于管理员权限，应由店长使用本人管理员账号办理 |
| 开单时找不到客户或宠物 | 检查是否已建档、是否归属该客户、是否被停用 |
| 服务价格与预期不一致 | 先核对宠物体重和服务体型档，再核对服务项目四档价格 |
| 次卡不能抵扣 | 核对是否属于当前客户、是否过期或作废、剩余次数、适用服务及抵扣行数量是否为 1 |
| 重复点击结账后担心重复单 | 先到“单据查询”按客户和时间核查，不要直接再次开单 |
| 商品有库存却无法销售 | 可能存在过期或不可用批次，应检查批次结存和库存流水，并运行数据体检 |
| 寄养入住提示疫苗过期或无记录 | 到客户详情点击“记一针”，补录有效疫苗或狂犬记录及正确到期日 |
| 新建寄养提示笼位冲突 | 检查该笼位其他待入住、在住订单的时间区间，换笼位或调整日期 |
| 退住金额没有扣押金 | 这是当前系统规则，押金需按门店线下记录另行核算 |
| 预约客户结账后仍要撤销 | 注意反结账不会恢复预约状态，先确认后续预约如何处理 |
| 日营业汇总与首页凌晨数据不同 | 日报按 04:00 营业日切点，首页部分“今日”指标按自然日；对账以日营业汇总口径为准 |
| 月报商品毛利偏高 | 检查商品成本价及销售批次成本是否完整 |
| 操作后查不到审计日志 | 当前审计不覆盖所有业务，改查对应单据、卡延期记录或库存流水 |
| 系统进入维护模式 | 停止业务操作；确认是在等待重启恢复，还是需要取消恢复准备 |

## 十五、店长操作红线

以下操作提交前必须复核：

1. **售卡不能反结账，确认客户、卡类型、实收金额和收款方式后再提交。**
2. **次卡作废不能恢复，也不等于退款。**
3. **只能反结账当前营业日普通销售单；预约和寄养状态不会自动恢复。**
4. **寄养入住必须有有效疫苗或狂犬记录，不得绕过检查。**
5. **退住结算不会自动扣押金，也不会因反结账恢复在住状态。**
6. **库存调整必须基于真实业务和凭证，不得用来掩盖销售或收款差异。**
7. **卡类型、服务项目当前不能直接编辑，新建时一次核对清楚。**
8. **删除店员账号不可恢复，管理员账号不得共用。**
9. **恢复备份会覆盖当前整库，准备恢复后必须停止业务写入。**
10. **自动备份不等于异地备份，店长应确认门店另有离线或异地副本。**

## 十六、店长交接建议

交接班或店长更换时，至少交接以下事项：

- 当日未结账、已反结账及异常单据；
- 待到店、已到店但未结账的预约；
- 在住、超期、应入住和应退住寄养单；
- 有特殊照护要求或异常记录的宠物；
- 待联系的重要到期提醒；
- 低库存、临期商品和待核对库存差异；
- 待处理的次卡延期、作废或售后事项；
- 最近一次备份时间及是否存在待执行恢复任务；
- 数据体检异常及其他未解决事项。
