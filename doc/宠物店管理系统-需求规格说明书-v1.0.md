## 1. 产品定位

> 给单店宠物店用的**客户资产台账**：一人多宠、卡里还剩几次、疫苗哪天到期，全部说得清、查得到、能追溯。

**不做的定位**：不是收银机（不做支付通道），不是营销工具（不做优惠券积分），不是 SaaS（不做多租户）。

### 1.1 目标用户

| 角色 | 是谁 | 每天做什么 | 系统给他什么 |
|---|---|---|---|
| 店主（ADMIN） | 老板，兼收银 | 看昨天卖了多少钱、给客户延期卡、处理纠纷 | 一眼看清营收构成、能反结账、能查每一笔核销 |
| 前台（STAFF） | 店员 | 建档、开单、核销次卡、打电话提醒 | 3 次点击完成一单，不用记价格 |

**前提假设**：单店、单机（或局域网内 1–3 台电脑访问同一台主机）、每天 30–80 单、客户量 200–2000。

### 1.2 行业逻辑（决定功能排序）

> **服务对象是宠物，付费对象是人；一人多宠，所以档案是父子结构；复购不靠促销，靠「到期提醒」；卡是资产，不是优惠券。**

三条例证：
1. 纸质卡盖戳记次，会员坚持剩 4 次、卡片只数出 2 次，甩一句「你们这卡有鬼」就去了隔壁店 → **纠纷成本 > 系统成本**
2. 通用会员 SaaS 用一个月沦为打卡钟 → 因为「划次 + 赠次分账」「疫苗核验」这两个概念在通用版里不存在
3. 国庆接 14 只寄养，节后发现两只疫苗过期六天 → **合规风险**

## 3. 业务流程

### 3.1 主流程（必须端到端跑通）

```
① 建档               ② 售卡                ③ 开单核销             ④ 看提醒
主人 + 宠物      →   洗护10次卡（送2次）  →  商品 + 洗护混单    →   疫苗/驱虫到期清单
疫苗记录一起录        记 paid/gift 分开      扣1次 + 收差额         打电话 → 标记已联系
```

**验收标准动作**：建档 3 个主人 4 只宠物 → 卖 1 张 10 送 2 洗护卡 → 开一单（1 袋狗粮 + 1 次洗澡，用卡抵扣）→ 卡剩 12 次、商品减 1、营收 = 狗粮金额 → 首页出现「3 天后疫苗到期：豆豆」。

### 3.2 单据状态机

```
        ┌──────────┐  结账   ┌───────────┐
        │   OPEN   │───────►│  SETTLED  │
        │（开单中） │        │（已结账）  │
        └────┬─────┘        └─────┬─────┘
             │ 取消                │ 反结账（仅 ADMIN + 当日）
             ▼                    ▼
        ┌──────────┐        ┌───────────┐
        │CANCELLED │◄───────│ CANCELLED │
        └──────────┘        └───────────┘
```

- `OPEN` 只能由「提交结账」进入 `SETTLED`，不能直接跳到 `CANCELLED` 之外的任何状态
- `CANCELLED` 是终态，不可恢复（需要恢复就重开一单）
- 反结账只允许**同一营业日**内操作，跨日禁止（防止改历史账）

### 3.3 次卡状态机

```
   ACTIVE ──到期──► EXPIRED ──延期──► ACTIVE
      │                 │
      └──作废（ADMIN）──►└──────► VOID（终态）
```

**关键规则**：`EXPIRED` 状态下**余额不清零**，仍可查询、可延期，只是不能核销。

### 3.4 营业日

- 营业日切点固定 **04:00**（不可配）。00:00–03:59 产生的单据归属**前一天**。
- 理由：宠物店晚间营业到 22:00 后常有补单，按自然日切会把营业额拆碎。
- `bill.business_date` 在结账时计算一次并落库，之后不再重算。

### M2 次卡

| 编号 | 需求 | 优先级 | 验收标准 |
|---|---|---|---|
| FR-M2-01 | 卡类型配置（名称、适用服务、付费次数、赠送次数、有效期天数、售价） | P0 | 总次数 = 付费 + 赠送，两个字段**分开存**，不合并不推导 |
| FR-M2-02 | 售卡（客户 + 卡类型 + 实收金额 + 收款方式） | P0 | 生成 `customer_card`，同时生成一张 `bill_type=CARD` 的收款单 |
| FR-M2-03 | 核销（开单时选卡抵扣服务项） | P0 | 每次核销写一条 `card_consume_log`，含订单号、明细 ID、操作人、时间 |
| FR-M2-04 | 剩余次数与赠次优先 | P0 | 剩余 = `paid_qty - used_paid + gift_qty - used_gift`（**实时算，不存字段**）；赠次优先可配；不允许扣成负数 |
| FR-M2-05 | 卡过期 | P0 | 过期不可核销（`CARD_EXPIRED`），但余额可查；延期后恢复可用并写延期记录 |
| FR-M2-06 | 卡流水查询 | P0 | 按客户/按卡查；每笔能追溯到具体订单，前台能当场给客户看 |
| FR-M2-07 | 卡作废 | P0 | 仅 ADMIN；已核销 > 0 时必须填原因；作废后终态不可恢复 |
| FR-M2-08 | 次卡余额表 | P0 | 全店在售卡一览：总次/已用/剩余/到期日，可按到期日升序（催续卡用） |

**为什么「剩余次数」不能存字段**：存了就一定会不同步（反结账、并发核销、手工改库都会让它漂移），而它恰恰是客户投诉的爆发点。宁可每次多算一个加法。

### M3 开单与收款

| 编号 | 需求 | 优先级 | 验收标准 |
|---|---|---|---|
| FR-M3-01 | 混合开单（商品 + 服务同一张单） | P0 | 一张单可含多条商品明细与多条服务明细 |
| FR-M3-02 | 服务项目与体型四档价（小/中/大/巨型） | P0 | 按宠物 `weight_g` 自动匹配档位：<10kg 小、10–25 中、25–40 大、>40 巨型；允许手工改档，改档后单价随之变 |
| FR-M3-03 | 服务类明细必须关联宠物 | P0 | 只买商品可不选宠物；含服务项且未选宠物时拒绝 `PET_REQUIRED` |
| FR-M3-04 | 次卡抵扣明细 | P0 | 抵扣后该明细金额记为 **0**，但计入核销统计、**不计入营收** |
| FR-M3-05 | 实收与收款方式 | P0 | 只记 `pay_method` 枚举与金额；**不找零入库、不接通道、不退款** |
| FR-M3-06 | 整单折扣 | P0 | 单一金额输入框；按明细金额占比分摊，**尾差归金额最大的明细** |
| FR-M3-07 | 反结账 | P0 | 仅 ADMIN + 必填原因 + 仅当日；同时回滚核销次数与库存流水 |
| FR-M3-08 | 单据查询 | P0 | 按日期区间/客户/宠物/单号查；结果分页 |
| FR-M3-09 | 单据详情与浏览器打印 | P0 | 详情页支持 Ctrl+P 打印/存 PDF；**不接热敏打印机驱动** |

**折扣分摊算法（必须写死，否则每次对账差几分钱）**：

```
1. 可分摊基数 = Σ(明细 amount)，不含已用次卡抵扣的明细
2. 每条明细折扣 = round(总折扣 × 该明细金额 / 基数)   ← 分，四舍五入
3. 尾差 = 总折扣 − Σ(各明细折扣)，加到金额最大的那条明细上
4. 明细折后金额 = 原金额 − 该明细折扣
5. 应收 = Σ(明细折后金额)
```

## 6. 业务规则（不可妥协，逐条实现）

| 编号 | 规则 | 违反后果 |
|---|---|---|
| **BR-01** | **赠次优先**：核销时若 `gift_remaining > 0` 且开关为真 → `used_gift + 1`；否则 `used_paid + 1` | 先扣付费次会让客户觉得「送的没给」，续卡率下降 |
| **BR-02** | **营收三类分列**：售卡收入（收款当日确认）/ 商品收入 / 服务收入；次卡抵扣明细金额记 0 且不计收入 | 卖 1200 元卡当天记「营收 1200」，实际是未来 12 次服务的预收，老板会误判经营状况 |
| **BR-03** | **剩余次数不落库**，实时计算 | 存字段必然不同步，这是客户投诉的第一来源 |
| **BR-04** | **流水只增不改**：`card_consume_log`、`product_ledger` 不允许 UPDATE/DELETE；冲销靠新增反向记录 | 改流水等于销毁证据，纠纷时无法自证 |
| **BR-05** | **金额全库用「分」存整数**；禁止 float/double/BigDecimal 入库 | SQLite 无 DECIMAL 类型，`0.1` 存进去取出来可能不是 `0.1`，对账差几分且极难查 |
| **BR-06** | **名称快照**：`bill_item.name_snapshot` 必须冗余存名称 | 服务项目改名后，历史单据金额与名称会一起变，没法解释 |
| **BR-07** | **核销与库存变更必须在同一事务内**，失败整单回滚 | 出现「扣了次数没扣库存」或反之，两边账都对不上 |
| **BR-08** | **反结账仅当日 + 仅 ADMIN + 必填原因**，且同步回滚次数与库存 | 允许改历史账 = 账目不可信 |

### 6.1 支付与资金边界（产品红线）

| 做 | 不做 |
|---|---|
| 结账只填**应收 + 收款方式枚举**（现金/微信/支付宝/银行卡/其他），仅记账 | 不接微信、支付宝、银联任何通道 |
| 售卡记实收金额与收款方式 | 不做退款（退卡只做作废 + 原因记录） |
| 次卡记**次数**（paid/gift/used） | **不做储值余额消费** |

**为什么次卡能做、储值不能**：次卡的本质是「服务提货权」，记的是次数，钱不在系统里流转；储值余额是「钱存在你店里」，涉及预付卡备案、资金存管、退款义务。前者是台账，后者是金融。

## 7. 数据口径（开发时逐条对照）

| 口径 | 规则 |
|---|---|
| 金额 | 全库 `INTEGER`，单位**分**；字段名统一 `_cent` 后缀 |
| 重量 | 全库 `INTEGER`，单位**克**；字段名 `_g` 后缀 |
| 数量 | 全库 `INTEGER`，不存在小数数量（宠物店不称重卖粮） |
| 日期 | `TEXT`，`yyyy-MM-dd` |
| 时间 | `TEXT`，`yyyy-MM-dd HH:mm:ss` |
| 布尔 | `INTEGER`，0 / 1，字段名 `is_` 或 `_flag` 前缀/后缀 |
| 营业日 | `TEXT` `yyyy-MM-dd`，04:00 切点，结账时计算一次落库 |
| 剩余次数 | 不存，实时 `paid_qty - used_paid + gift_qty - used_gift` |
| 年龄 | 不存，实时按生日算 |
| 库龄/在店天数 | P0 不涉及（寄养在 P1） |

## 8. 非功能需求

### 8.1 部署与运行

| 项 | 要求 |
|---|---|
| 运行环境 | **JDK 1.8**（32/64 位均可）；不要求装数据库、不要求装 Tomcat |
| 交付物 | 单个 `pet-shop.jar` + `start.bat` + `start.sh` + `config/` + `schema/` |
| Windows 启动 | 双击 `start.bat`，无需命令行、无需管理员权限 |
| Linux 启动 | `./start.sh`，支持 nohup 后台运行，写 PID 文件 |
| 数据目录 | jar 同级 `data/pet.db`；**不得写入程序安装目录以外的地方** |
| 端口 | 默认 8080，被占用时提示并允许改 `config/application.yml` |
| 首次启动 | 自动建库建表 + 初始化管理员账号 + 示例数据（可关闭） |
| 断网可用 | **所有静态资源本地化，禁止引用任何 CDN** |

### 8.2 性能

| 场景 | 指标 |
|---|---|
| 页面首屏（局域网） | P95 < 800ms |
| 开单页加入 10 条明细 | 每次操作响应 < 200ms（纯前端计算，不请求后端） |
| 结账提交 | P95 < 500ms |
| 客户/单据列表 | 单页 20 条，翻页 < 300ms |
| 数据规模目标 | 客户 2000、宠物 3000、单据 10 万单，上述指标不退化 |

### 8.3 可靠性

| 项 | 要求 |
|---|---|
| 事务 | 结账、核销、库存变更、反结账必须原子 |
| 备份 | 每日自动 + 手动按钮；保留最近 7 份 + 每月 1 号 1 份月备份 |
| 断电 | SQLite WAL 模式，断电不损坏库；重启后事务自动回滚 |
| 误删 | 单据与流水只允许逻辑作废，不允许物理删除 |
| 日志 | 按天滚动，保留 30 天，输出到 `logs/` |

### 8.4 易用性

| 项 | 要求 |
|---|---|
| 开单效率 | 一单纯商品 ≤ 4 次点击（搜商品 → 加入 → 结账 → 确认） |
| 学习成本 | 店员无需培训即可开单；关键操作有中文提示，不出现英文错误码 |
| 屏幕适配 | 1366×768 起可用；前台平板（1024 宽）不横向滚动 |
| 字体 | 中文无乱码（Windows 下必须显式设 UTF-8） |

### 8.5 安全

| 项 | 要求 |
|---|---|
| 密码 | BCrypt（strength 10），**禁止明文与 MD5** |
| 会话 | HttpSession，8 小时超时；未登录访问任何页面跳登录页 |
| 越权 | 服务端二次校验角色，前端隐藏按钮**不作为**权限手段 |
| SQL 注入 | 全部走 MyBatis `#{}` 参数绑定，**禁止 `${}` 拼接** |
| 数据 | 数据库文件不加密（本版），依靠操作系统文件权限；备份文件同目录 |
| 上传 | P0 不支持图片上传（宠物头像用预置图标） |

## 9. 边界与异常场景（26 条，开发自测用）

| # | 场景 | 系统应有行为 |
|---|---|---|
| 1 | 重复手机号建档 | 返回 `CUSTOMER_EXISTS`，保留已填内容不清空 |
| 2 | 一人同名两只狗 | 允许，宠物名不唯一 |
| 3 | 宠物生日晚于今天 | 拒绝，提示「生日不能晚于今天」 |
| 4 | 生日为空 | 年龄显示「—」，不影响开单 |
| 5 | 卖 10 送 2 的卡 | `paid_qty=10, gift_qty=2`，账面剩余 12 |
| 6 | 核销第 1 次（赠次优先开） | `used_gift=1`，剩余 11 |
| 7 | 扣到 0 次再核销 | 拒绝 `CARD_NO_BALANCE`，不产生流水 |
| 8 | 过期卡核销 | 拒绝 `CARD_EXPIRED`，但余额仍可查 |
| 9 | 过期卡延期 30 天 | 状态回 `ACTIVE`，`expire_on` 后移，写延期记录 |
| 10 | 作废一张已核销 3 次的卡 | 必须填原因，作废后不可核销、不可恢复 |
| 11 | 一单含狗粮 + 洗澡，洗澡用卡抵 | 洗澡明细金额 0；应收 = 狗粮金额；核销流水 +1 |
| 12 | 同一单用两张卡抵两个服务 | 允许，两条明细各扣各的卡 |
| 13 | 一张卡被两单同时核销（双击） | 只有一单成功；另一单因余额不足失败，不得出现负剩余 |
| 14 | 含服务项但未选宠物 | 拒绝 `PET_REQUIRED` |
| 15 | 只买商品不选宠物 | 允许 |
| 16 | 体重 25.0kg | 归「大型」档（区间左闭右开，边界取大档） |
| 17 | 手工改档为「巨型」 | 单价按巨型取，改档记录在明细里 |
| 18 | 整单折扣 10 元，3 条明细 | 分摊后尾差归金额最大那条，合计恰为 10 元 |
| 19 | 折扣大于总额 | 拒绝，应收不得为负 |
| 20 | 结账时重复点击提交 | 只生成一张单（表单 token 幂等） |
| 21 | 反结账后再查该单 | 状态 `CANCELLED`；次数与库存已回滚；操作人原因可见 |
| 22 | 跨日反结账（昨天的单） | 拒绝 `BILL_NOT_TODAY` |
| 23 | 商品库存 1 件，两单同时卖 | 只有一单成功，另一单 `STOCK_NOT_ENOUGH` |
| 24 | 直接访问别的客户的卡 | 不涉及（单店无跨店），但须登录 |
| 25 | 数据库文件被占用/损坏 | 启动报明确中文错误，提示备份位置，不静默失败 |
| 26 | 端口 8080 被占用 | 启动失败并提示改端口的具体文件路径与行号 |

## 10. 验收清单（20 条，逐条点过才算交付）

1. 首次双击 `start.bat` 能启动，8 秒内浏览器自动打开登录页。
2. 第二次启动不丢数据，`data/pet.db` 存在且时间戳更新。
3. 未登录访问 `/customers` 跳转登录页。
4. 默认账号 `admin` 能登录，错误密码提示不泄露「用户是否存在」。
5. 一个客户挂 3 只宠物，详情页一次看全（宠物 / 持卡 / 近 10 单 / 提醒）。
6. 生日为空的宠物，年龄显示「—」。
7. 卖 10 送 2 卡后，余额表显示 12 次。
8. 核销 1 次后剩 11，且流水里 `from_gift=1`。
9. 卡扣到 0 后再核销被拒，且未产生流水记录。
10. 一张单含狗粮 + 洗澡并用卡抵扣，实收只有狗粮钱。
11. 次卡抵扣明细金额为 0，当日「服务收入」不增加，「核销次数」增加 1。
12. 日营业汇总三列之和 = 当日实收总额（拿计算器核对）。
13. 整单折扣 10 元后，明细合计恰为 10 元，无尾差。
14. 反结账后，核销次数、库存、单据状态三者同时回滚。
15. 昨天开的单不能反结账。
16. 疫苗记录保存后到期日为 +365 天，且在 30 天提醒窗口内出现。
17. 逾期项显示「已逾期 X 天」且标红；标记「已电话」后从待处理消失、记录保留。
18. 商品卖 1 件后库存 -1、流水 +1；页面上找不到任何「直接改库存数」的输入框。
19. 全站断网可用（拔网线刷新页面样式正常）。
20. 手动备份生成的文件能用 SQLite 工具打开且数据完整。
