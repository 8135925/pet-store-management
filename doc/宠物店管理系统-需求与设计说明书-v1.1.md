## 1. 本期要解决的真实问题

### 1.1 为什么是寄养

P0 上线试运行后最直接的反馈：**节假日寄养接单全靠一个本子**。真实痛点：

1. 笼位 20 个，旺季接 30 单，前台靠记忆排笼 → 撞笼、漏接、算错天数
2. 接寄养不看疫苗 → 一只细小病毒潜伏期传染半屋，赔掉全年利润
3. 退住结账现场算账：「住了 5 晚还是 6 晚？加喂罐头谁记的？」→ 纠纷高发
4. 每天喂食遛弯没人留痕 → 客户来接时问「昨天喂了几顿」答不上来

> 需求规格 v1.0 §1.2 的例证 3（「国庆接 14 只寄养，节后发现两只疫苗过期六天 → 合规风险」）是本期最优先要消除的风险。

### 1.2 为什么是预约

1. 周末美容档期靠电话小本子记录 → 撞单、爽约无追踪
2. 客户到店才发现美容师排满 → 流失
3. 预约到店后还要重新查档案、问做什么项目 → 前台重复劳动

### 1.3 顺带解决的高频小事（试运行反馈）

1. 狗粮条码扫码开单（P0 已存条码，只差一个输入框）
2. 老板月底想看「这个月卖了多少、毛利多少」——P0 只有日汇总
3. 给客户打电话要回客户列表翻手机号
4. v1.0 验收遗留的 4 处缺口（§9）

## 3. 业务规则（新增，延续 BR-01~BR-08）

| 编号 | 规则 | 违反后果 |
|---|---|---|
| **BR-09** | **疫苗拦截**：办理入住时，该宠物必须存在疫苗或狂犬记录，且最近一条的 `next_due_on ≥ 入住开始日`；**没有任何记录视为过期**，一律拦截 `VACCINE_EXPIRED` | 细小/犬瘟交叉感染一次 = 赔掉全年利润（v1.0 §1.2 例证 3） |
| **BR-10** | **笼位互斥**：同一笼位时间区间重叠禁止入住。冲突判定：`new_start < old_end_at AND old_start_at < new_end`（已 CANCELLED/CHECKED_OUT 的单不参与） | 一笼两狗 = 打架受伤 = 纠纷 |
| **BR-11** | **按晚计费**：计费晚数 = 实际退住日 − 入住日，**最少 1 晚**，不足一天按一天；预离店日之后继续占用，退住时按实际天数结，不另收超时费 | 按小时计费在宠物店无真实场景，徒增纠纷 |
| **BR-12** | **金额红线延续**：寄养费、预约转开单一律走「分」，寄养结算生成普通 SALE 销售单，走现有收款流程，**不新增资金形态** | 账目口径分裂，日汇总对不上 |
| **BR-13** | **寄养与预约互斥提示**：宠物在店寄养期间再建到店预约 → 允许但强制提示「该宠物正在寄养中」 | 双重占用笼位/美容工位 |
| **BR-14** | **每日记录只增不改**：寄养期间的喂养/遛弯记录按天 INSERT（一天一条，可补录，不可改删） | 客户问「昨天喂了几顿」时答案必须唯一 |

## 4. 数据库设计（v1.1 新增 4 表，全部 `IF NOT EXISTS` 幂等追加到 schema.sql 末尾）

### 4.1 boarding_room 笼位

```sql
CREATE TABLE IF NOT EXISTS boarding_room (
  id         INTEGER PRIMARY KEY AUTOINCREMENT,
  code       TEXT    NOT NULL,               -- 笼位编号 R01/R02/C01…（C 开头为猫位）
  room_type  TEXT    NOT NULL,               -- 适用类型：S / M / L / XL / CAT（对齐体型档）
  daily_price_cent INTEGER NOT NULL DEFAULT 0, -- 该笼位每晚挂牌价（可被寄养单单价覆盖）
  note       TEXT,                           -- 位置说明（靠窗/带跑笼）
  is_active  INTEGER NOT NULL DEFAULT 1,     -- 维修中可停用
  created_at TEXT    NOT NULL
);
CREATE UNIQUE INDEX IF NOT EXISTS uk_room_code ON boarding_room(code);
```

### 4.2 boarding_order 寄养单

```sql
CREATE TABLE IF NOT EXISTS boarding_order (
  id               INTEGER PRIMARY KEY AUTOINCREMENT,
  order_no         TEXT    NOT NULL,        -- 单号 B + yyyyMMdd + 4位序号，如 B202610260001
  customer_id      INTEGER NOT NULL REFERENCES customer(id),
  pet_id           INTEGER NOT NULL REFERENCES pet(id),
  room_id          INTEGER NOT NULL REFERENCES boarding_room(id),
  start_at         TEXT    NOT NULL,        -- 入住时间 'yyyy-MM-dd HH:mm'（预约制可填未来）
  planned_end_on   TEXT    NOT NULL,        -- 预计离店日 'yyyy-MM-dd'
  end_at           TEXT,                    -- 实际退住时间；未退住为 NULL
  days             INTEGER,                 -- 计费晚数（退住结算时落库，≥1）
  unit_price_cent  INTEGER NOT NULL,        -- 实际每晚价（下单时快照，改价不回改）
  deposit_cent     INTEGER NOT NULL DEFAULT 0, -- 押金，仅记账展示，不进营收、不进余额
  status           TEXT    NOT NULL DEFAULT 'BOOKED',
                   -- BOOKED 已订未住 / CHECKED_IN 在住 / CHECKED_OUT 已退住结算 / CANCELLED 已取消
  bill_id          INTEGER,                 -- 退住结算生成的 bill.id
  remark           TEXT,
  created_at       TEXT    NOT NULL,
  created_by       TEXT
);
CREATE INDEX IF NOT EXISTS idx_bo_room_time ON boarding_order(room_id, start_at); -- 冲突检测
CREATE INDEX IF NOT EXISTS idx_bo_status    ON boarding_order(status);            -- 在店清单
CREATE INDEX IF NOT EXISTS idx_bo_customer  ON boarding_order(customer_id);
```

### 4.3 boarding_log 寄养每日记录

```sql
CREATE TABLE IF NOT EXISTS boarding_log (
  id         INTEGER PRIMARY KEY AUTOINCREMENT,
  order_id   INTEGER NOT NULL REFERENCES boarding_order(id),
  log_date   TEXT    NOT NULL,              -- 记录的是哪一天（允许补录昨天）
  fed_count  INTEGER NOT NULL DEFAULT 0,    -- 喂食次数
  walked     INTEGER NOT NULL DEFAULT 0,    -- 是否遛弯 0/1
  note       TEXT,                          -- 精神状态/大便情况/异常
  operator   TEXT,                          -- 记录人
  created_at TEXT    NOT NULL
);
CREATE UNIQUE INDEX IF NOT EXISTS uk_blog_order_date ON boarding_log(order_id, log_date); -- 一天一条
```

### 4.4 appointment 预约

```sql
CREATE TABLE IF NOT EXISTS appointment (
  id          INTEGER PRIMARY KEY AUTOINCREMENT,
  customer_id INTEGER NOT NULL REFERENCES customer(id),
  pet_id      INTEGER NOT NULL REFERENCES pet(id),
  service_id  INTEGER NOT NULL REFERENCES service_item(id),
  appoint_date TEXT   NOT NULL,             -- 预约日
  slot        TEXT    NOT NULL,             -- 时段 'HH:mm'，粒度 30 分钟（09:00~21:30）
  size_tier   TEXT,                         -- 建单时宠物体型档快照（估价用）
  status      TEXT    NOT NULL DEFAULT 'BOOKED',
              -- BOOKED 已预约 / ARRIVED 已到店 / DONE 已转开单 / CANCELLED 已取消 / NO_SHOW 未到
  bill_id     INTEGER,                      -- 转开单后的 bill.id
  remark      TEXT,
  created_at  TEXT    NOT NULL,
  created_by  TEXT
);
CREATE INDEX IF NOT EXISTS idx_appt_date ON appointment(appoint_date, slot);
```

## 5. 状态机

### 5.1 寄养单

```
        ┌────────┐  办理入住(疫苗校验+笼位锁)   ┌────────────┐  退住结算(生成账单)  ┌──────────────┐
        │ BOOKED │ ─────────────────────────► │ CHECKED_IN │ ─────────────────► │ CHECKED_OUT  │
        │ 已订未住│                             │  在住       │                    │ (终态)        │
        └───┬────┘                             └────────────┘                    └──────────────┘
            │ 取消(未入住随时可取消)                  │
            ▼                                       │ 改预离店日(延期/提前，改 planned_end_on)
        ┌────────────┐                              ▼
        │ CANCELLED  │                        仍为 CHECKED_IN（留下变更说明于 remark）
        └────────────┘
```

- `CHECKED_OUT` / `CANCELLED` 是终态
- 改预离店日 = 提前或延后笼位占用区间 → **每次修改都重跑 BR-10 冲突检测**
- 已入住房间不可换笼（换笼 = 先退住再重开，留下完整轨迹）

### 5.2 预约

```
        ┌────────┐   到店    ┌────────┐  转开单(生成SALE单)  ┌──────┐
        │ BOOKED │ ───────► │ ARRIVED │ ──────────────────► │ DONE │
        └───┬────┘          └────────┘                     └──────┘
            │                    │
            ├─取消─► CANCELLED   ├─客户走了没消费→ NO_SHOW
            └─当天未到→（次日批量/手工标 NO_SHOW）
```

- `ARRIVED` 后不可取消，只能转开单（哪怕空单也要走开单页，金额 0 允许？——不允许，开单明细非空）
- `DONE` 的预约上显示单号链接，可跳转单据详情

## 7. 关键流程详设

### 7.1 F7 新建寄养单（事务）

```
输入：customerId, petId, roomId, startAt, plannedEndOn, unitPriceYuan, depositYuan, remark
事务开始
  1. 校验客户 is_active=1、宠物存在且属于该客户
  2. 校验笼位存在且 is_active=1
  3. 校验 plannedEndOn > startAt 的日期部分
  4. ★ BR-10 冲突检测：
     SELECT count(*) FROM boarding_order
     WHERE room_id=#{roomId} AND status IN ('BOOKED','CHECKED_IN')
       AND start_at < (plannedEndOn || ' 23:59')
       AND (COALESCE(end_at, planned_end_on || ' 23:59')) > startAt
     > 0 → ROOM_OCCUPIED（提示占用单号）
  5. ★ BR-09 疫苗校验（入住时点检查即可，BOOKED 阶段仅提示不拦截）：
     SELECT MAX(next_due_on) FROM pet_event
     WHERE pet_id=#{petId} AND event_type IN ('VACCINE','RABIES')
     无记录 或 MAX < startAt日期 → VACCINE_EXPIRED
  6. INSERT boarding_order（unit_price 快照；BOOKED 状态）
事务提交
```

**疫苗校验放在「办理入住」时**也执行一次（BOOKED → CHECKED_IN 是唯一强制点）：预约了三个月后入住的宠物，可能这周刚好该打疫苗。

### 7.2 F8 退住结算（事务）

```
输入：orderId, payMethod, 实际退住时间
事务开始
  1. 校验 status='CHECKED_IN' → 否则 BOARDING_NOT_IN
  2. days = max(退住日 − 入住日, 1)        ← BR-11 按晚计费
  3. UPDATE boarding_order SET end_at=?, days=?, status='CHECKED_OUT'
  4. INSERT bill(bill_type='SALE', status='SETTLED', business_date=BusinessDate.of(now),
                 pay_method=?, request_id='BO-' + order_no)   ← 复用幂等键格式防重复结算
  5. INSERT bill_item(item_type='BOARDING', ref_id=order.id,
                      name_snapshot='寄养·' + 宠物名 + '·' + days + '晚',
                      unit_price_cent=快照单价, qty=days, amount_cent=单价×晚数)
  6. UPDATE boarding_order SET bill_id=?
事务提交
```

寄养费若要**当场用次卡抵扣**（FR-M8-10）：不走 F8 直接收款，而是跳转开单页（预填客户/宠物 + 一条自定义寄养明细），由前台在开单页正常选卡结账——寄养单仍标 CHECKED_OUT 并回写 bill_id。**两条路都存在，前台按场景选**。

### 7.3 F9 预约转开单

```
  1. 校验 status='ARRIVED'
  2. 跳转 /bills/new?customerId=..&petId=..&appointmentId=..
  3. 开单页前端按 appointment.service_id 预填一条服务明细（档位取当前体重自动档）
  4. 结账成功 → UPDATE appointment SET status='DONE', bill_id=?
     （在 settle 事务内回写，保证「单在预约必 DONE」）
```

### 7.4 商品成本快照（毛利口径）

P0 的 `product.cost_price_cent` 是可改的当前值，直接用它算历史毛利会漂。本期在扣库存时把成本**快照进流水**：

```sql
ALTER 语义：product_ledger 新增列 remark 已有，不新增列——
毛利 = SUM(bill_item.amount_cent − unit_cost_cent)，
unit_cost_cent 从 product_ledger 取该单 SALE 流水的快照。
```

结论：**给 product_ledger 加一列 `unit_cost_cent INTEGER NOT NULL DEFAULT 0`**（SQLite `ALTER TABLE ADD COLUMN` 幂等执行需捕获 duplicate column 容错，写进 schema.sql 时用注释标注 v1.1 增列）。历史 P0 数据该列为 0，毛利报表按 0 展示即可。

## 10. 边界与异常场景（16 条，开发自测用）

| # | 场景 | 系统行为 |

| 1 | 给无任何疫苗记录的宠物办入住 | 拦截 `VACCINE_EXPIRED`（无记录视为过期） |

| 9 | 寄养 3 晚，超期 2 天才接走 | 结算 5 晚（按实际晚数） |

| 12 | 同一时段第 4 个预约（容量 3） | 拒绝 `SLOT_FULL` |
| 13 | 预约到店后客户什么都没做就走了 | 标 NO_SHOW，不产生单据 |

| 16 | 笼位停用时还有在住宠物 | 允许停用（不影响在住），但不出现在新单选择框 |

## 12. 验收清单（18 条，逐条点过才算交付）

1. 建笼位 20 个（S/M/L/XL/CAT），编号唯一，停用不出现在新单。
2. 给无疫苗记录的宠物办入住被拒，提示含具体原因。
3. 疫苗过期前 1 天入住放行，过期后 1 天被拒。
4. 同笼重叠时段第二单被拒，提示占用单号；退住后同笼可再入住。
5. 寄养 5 晚提前 1 天接走，结算 4 晚，金额 = 单价 × 4。
6. 寄养账单出现在日营业汇总「服务收入」列，寄养当天的三列之和 = 实收。
7. 每日喂养记录一天一条，补录昨天有效，重复提交被拒。
8. 在店看板显示已住晚数与预离店日，超期未接标红。
9. 修改预离店日加晚 2 天，笼位冲突检测重新生效。
10. 预约时段满 3 个后第 4 个被拒；取消一个后可再约。
11. 预约到店 → 转开单，服务项已预填，结算后预约状态 DONE 且可跳单据。
12. 宠物在店寄养时建预约出现强提示。
13. 首页看板 8 数字：在店数、今日预约数与明细一致。
14. 扫码枪扫狗粮条码，明细自动加入且光标回到条码框。
15. 月度汇总切换上月，三列与合计行正确，商品毛利列有值。
16. 提醒清单电话可点击拨号（手机）并可复制。
17. 单据查询可按宠物筛选出该宠物参与过的单（含寄养结算单）。
18. `mvn test` 3 个单测通过；`app.sample-data=false` 首次启动只有 admin 无演示数据。
